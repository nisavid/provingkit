# Carry the probe procedure into execution

The maintained experimental procedure for this increment is
[probe-procedure.md](probe-procedure.md), together with its
[authorization checklist](authorization-checklist.md), source files, and build
receipt. It belongs to this retained Provingkit experiment and is not installed
agent equipment.

The authorization and execution tickets must invoke
`capturing-agent-procedures`, load the published revision, and verify the source
and candidate identities before acting. Authorization checks the concrete
scope; execution additionally checks the user's positive grant. The return
decision consumes the same revision and reports observations against its
completion criteria, preserving unresolved claims as prerequisites for the
notification route.

The applicable request is preparing or executing this exact disposable
no-send probe. A request to notify an existing peer, qualify delivery, inspect
another task, or install a maintained adapter does not enter this procedure.
Its no-op case is a missing or mismatched live grant: report the missing scope
and perform no dependent live step.

After qualification and an ownership decision, propose maintaining the app
adapter and patch with the repository that owns the selected Desktop package
integration. The standalone reader and focused peer-notification skill belong
in Rolecasting, as already selected for the route. No package-maintainer policy
or permission to edit another repository is inferred here. Adoption must name
that source and its maintenance checks before installing durable equipment.

Independent review of this increment must cover the procedure's entry
conditions, exact inputs, stop branches, restoration, and consumer pointers.
No new skill package is created or submitted to a skill evaluator. This capture
supports the bounded experiment; broader installation and reusable-skill
evaluation remain with the later adoption work.
