**Browser SSE.** [browser-sdk.d.ts](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.296/browser-sdk.d.ts), L27–76, declares `streamUrl`, `sendUrl`, CCR `sessionId`, shared headers, initial cursor, truncation callback, and delivery callback. Authorization and anthropic-client-platform are explicitly named; accepted credentials, platform values, supported external access, and mapping from a cloud task reference to that CCR ID remain unknown. L94–104 selects exactly one transport and prefers SSE.

[browser-sdk.js](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.296/browser-sdk.js) owning symbols are `WTe` (exported query; zero-based UTF-8 byte 1412441), `If` (Query; byte 818543), and `qm` (SSE transport; byte 1253216). Query construction starts connection/read machinery, calls initialize, and starts prompt consumption. Initialize sends a control request even with an empty prompt iterable. Hooks, tool permissions, SDK MCP servers, JSON schema, and prompt-suggestion options participate in control handling. Their presence does not prove unchanged remote configuration or benign concurrent-client effects.

`qm.connect` GETs streamUrl with Accept text/event-stream and, after a known wire cursor, Last-Event-ID. `qm.postOnce` (byte 1261482) POSTs sendUrl with JSON `{session_id, events:[{payload}]}`. `write` supplies a UUID if missing and queues through `Y1`. Successful write return means queueing/backpressure completion; POST success bodies are drained rather than returned as a durable event receipt. No public query result immediately supplies the authoritative event ID of a sent prompt.

Durable client_event frames provide event_id and sequence_num, optionally created_at and source. The transport strips payload ccr_event and stores the delivering envelope in a WeakMap keyed by the exact yielded object. `getCcrEvent(query,message)` returns that association; copies, constructed objects, WebSocket messages, and ephemerals do not acquire it (types L159–184). Envelope source is a transport/server channel, not authenticated ChatGPT author identity. SDK message UUID, control request_id, durable event_id, CCR session ID, result session_id, and application correlation must be recorded distinctly.

The source filters non-worker output types, worker-output-shaped user content, malformed user arrays, and forged replies matching this client's control request IDs. Normal peer/user text can remain sender-authored. `G4_TEXT_ENVELOPE_ARM_PORTED` is true in these bytes (`XV`, byte 1253141); that source value is no deployed security attestation.

`getSseLastSequenceNum` covers only yielded durable messages: `If.readSdkMessages` marks immediately before yield (byte 831876). Internal `lastSequenceNum` advances on wire frames, including frames later dropped or consumed. Dense session numbering therefore permits gaps between yielded messages. A caller that stops with buffered messages must preserve the yielded cursor, not substitute the internal reconnect cursor. Drop counts, truncation events, and separate REST catch-up/reseeding remain necessary; no REST event-list implementation is supplied.

Delivery updates acknowledge event_id and distinguish RECEIVED, PROCESSING, and PROCESSED; the types explicitly say updates are not durable/replayed. Preserve observed updates locally, treat unknown statuses as informational, and retain missed updates as missing evidence. A durable echo establishes an event record; worker receipt and processing establish different stages. PROCESSED does not establish semantic fulfillment.

**Legacy WebSocket.** The same browser types L22–26 and implementation `mk` (byte 1263842) use globalThis.WebSocket(url), an optional auth frame, newline-delimited messages, and keep-alive. **Worker bridge.** [bridge.d.ts](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.296/bridge.d.ts), L96–119 and L236–249, declares attachBridgeSession with worker JWT, API base, epoch, and replay cursor. ## Proposed work, evidence model, and public test boundary

Use the same invented no-edit work for each selected candidate: correlation demo-566-01; supplied words oak, birch, elm; supplied numbers 2, 3, 7; return only correlation, requested target specimen, alphabetically ordered words, and total 12. A worker “done” claim or PROCESSED update cannot pass these checks. Result extraction recognizes type=result, subtype, is_error, result/structured_output, errors, session_id, uuid, optional user_message_uuid/user_message_uuids, and result_index. The main declarations L5763–5769 document batch/folded prompt correlation; require membership rather than assume one request equals one turn. Propose a pure reducer taking a declared operation contract plus immutable evidence observations. Retain separate milestones submitted, receipt, accepted, executing, output, fulfilled; outcomes queued/held/refused/stale/incomplete/unknown; and observation completeness. Keep durable echo, delivery status, SDK result, and semantic validation as separate inputs. Evidence carries source/build/date, caller/target/owner mapping, correlation/UUID/event/turn keys, observation time, cursor/drop/gap state, output digest, checks, and limits. A follow-up continuation additionally needs requested/resolved same-task identity and a predeclared prior-context marker; replacement/fork remain separate.

Before implementation, agree a public boundary: given declared work and observations, expose reached milestones, unresolved gaps, and resend disposition. Proposed cases are queued exit only; correct correlated result; PROCESSED with wrong total; unrelated result; missing/batched UUIDs; error result; forged payload envelope/copy; buffered yield cursor; consumed-control sequence gap; truncation requiring catch-up; lost nondurable update; held/refused; and lost POST response with possible submission. These are proposed cases, not run tests or a synthetic pass.

Source retry mechanics constrain that design. SSE has 15-second connection, 45-second liveness, 30-second POST limits, five consecutive reconnect attempts (reset on successful connection), and uploader retry/drop behavior after three consecutive failures. Y1 enqueue starts draining without awaiting each POST; nonpermanent errors can requeue identical serialized payloads with backoff/Retry-After. Permanent 401/403/404 close the transport. This does not establish server deduplication or safe mutation retry after possible submission. Reconnect is read recovery; POST retries are writes. A lost response preserves unknown submission and requires reconciliation before any additional resend.
