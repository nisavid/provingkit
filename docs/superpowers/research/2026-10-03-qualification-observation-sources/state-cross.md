## New existing interface: sandbox dialog is useful and has effects

Both first reports omitted an existing SDK/Engine route. Stable SDK `getSandboxDialog()` sends `get_sandbox_dialog`; the retained Engine dispatches it to `buildSandboxDialogResponse`, subject to its connection check. [SDK `[1108100,1108350)`; Engine `[221196668,221197080)`.]

The builder returns platform support, policy locks, enabled/settings-enabled state, unavailable reason, mode/auto-allow, unsandboxed-command policy, dependency results, exclusions, and selected filesystem/network restrictions. Its restriction arrays come from `Xn()?.sandbox`, while enabled/policy fields use runtime helper methods. It therefore combines configured and runtime-derived facts; it is not a complete applied sandbox or permission snapshot. [Engine `[232011440,232012820)`.]

It also begins with settings invalidation and can perform dependency checking/configuration seeding. The settings helper `ws` invalidates its owner's state; the sandbox dependency path can call `Xl(pm(Xn() ?? {}))`, with a defaults fallback, and update probe caches. Lower-level dependency checking can perform platform-specific preparation. [Engine `[197935800,197938700)`, `[202839900,202841200)`, `[202742000,202742900)`.]

**Reconciliation:** include this route in the existing-interface alternatives, with its mixed semantics and operating effects. Do not silently add it to a passive permission sample, call its settings arrays “applied,” or adopt it as a substitute for the raw permission/sandbox owner projection. Trace and approve its exact selected-platform footprint before any live use. This finding reduces the claim that all sandbox diagnostics need new producers; it does not close complete applied permissions.

## Effects, acquisition, and time remain separate

The access report correctly distinguishes source-method presence from a usable existing caller. Renderer IPC is app-bound, the owning-task MCP route has tool/conversation effects, and SDK getters need the already captured query. No current external passive attachment or in-process hot-load path has been demonstrated.

A startup-loaded adapter observes the candidate's query after launch and independent selection. Restarting ordinary Desktop replaces preexisting query objects and interrupts tasks. Reusing a Code conversation ID after resume does not preserve the original query or observation boundary. Candidate launch/profile isolation, actual executor, restoration and ordinary-runtime transfer remain separate obligations.

The proposed file phase slots introduce polling, filesystem I/O and retention. The fallback callback adds receive-loop scheduling and serialization. Engine descriptors add source/build compatibility, memory/lifecycle maintenance, and the cost of loading changed executor bytes. Any load/restart effect and duration must be measured in the later reviewed experiment. The app-only design's interruption estimate cannot cover an undeveloped Engine intervention.

Do not call browser/computer-use helpers “pure” as a blanket claim before closing their cold configuration/gate/cache paths. Record evaluator inputs and actual clock argument. Computer-use expiry is a real applicable grant distinction: `Kqn`/`Jqn` accept a time argument and apply dispatched-session expiry. [Common `[3692300,3693500)`.]

A filter over the broker's global pending map acquires other entries' session IDs before retaining the selected entries. That is broader acquisition than a selected-session result. Choose a disclosed bounded inspection or a separately reviewed index. The relevance filter does not erase that footprint.

Existing settings/rules/status/summary control replies can acquire broader source/path/context/credential-display data before projection. Output-only caps do not bound those upstream reads. A promise race bounds result admission, not getter execution, reply bytes, or retained request handlers. Late results and cancellation effects remain explicit; do not close the task's query to clean up an observer timeout.

Host, Engine, SDK transport, hook event, UI/executor witnesses and their clocks remain named separately. Preserve producer time when supplied, request/reply or capture interval otherwise, and cached initialization's original date. One phase label does not make these observations simultaneous.
