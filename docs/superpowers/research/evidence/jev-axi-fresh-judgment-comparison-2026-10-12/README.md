# Fresh evidence-scope judgment comparison

This preparation compares two ways of asking Jev and the agreed ordinary models whether a statement is warranted by its supplied sources. It tests a possible early System One check before investing in delivery into working drafts.

The [execution contract](contract.md) proposes 144 serialized requests: twelve fresh synthetic cases, six model conditions, and two question formulations. The [questions](questions.json) preserve the existing four [answer meanings](relations.json). No experiment is authorized by this source checkpoint.

The cases distinguish a supported concise statement, an unsupported extension, an explicitly incompatible fact, and a genuinely unresolved reference or conflict. [Construction](construction.json) identifies complete source files and enclosing draft context. The local unavailable-source control makes no model request. The [answer key](evaluator/key.json), [grading procedure](evaluator/grading.md), and [independent labeling](evaluator/label-review.md) are evaluator-only material.

The first independent label pass found that the handover accounts did not exclude motor-assisted manual operation or different openings. The revised accounts describe the same sole opening and explicitly disagree about motor operation. That pass also lacked the existing rule for derivative evidential warrant; a fresh isolated label pass received all established meanings and agreed with the final twelve labels. The original reports remain retained by the coordinator. Neither pass saw question treatments or an expected key.

This is a deliberately explicit diagnostic set. It is fresh relative to the earlier model experiments, but it was constructed with their failure mechanisms in mind and is not a representative holdout sample. Success cannot establish calibration, useful intervention in native work, lower operator effort, or cheaper whole workflows. Model comparisons at this stage answer whether wording merits further development; omission and deterministic preparation remain eligible in later workflow comparisons.
