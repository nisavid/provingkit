## Recommended next preparation

The relevant question is whether the proposed representation can be produced without consuming the expensive reasoning it is meant to save. A source may already have stable item IDs and a complete bounded list of candidates. That differs from asking an ordinary model to discover every possible meaning of arbitrary prose. The latter may perform most of the semantic work before Jev sees the statement.

For a preparation proposal, identify one real supported input with existing identities and selectors. Trace how the original statement, valid alternatives, qualifications, and evidence become available. Separate deterministic selection from semantic interpretation. Explain which remaining relation Jev would judge and how it would differ from code alone, ordinary reasoning, omission, and the agreed ordinary-model alternatives. Count source acquisition, branch production, every judgment, combination, fallback, and downstream inspection. A larger number of cheap calls is not by itself a saving.

The design report's seven-assertion lamp example is a possible later rejection test, not an accepted fixture or experiment. Its material-ambiguity, immaterial-ambiguity, negation, unsupported-extension, and explicit-selection contrasts would test a different representation. Success would establish only narrow judgment feasibility. Missing or expensive preparation can still defeat the integration, and an invalid response or missing input must not be counted as a successful semantic abstention.

If complete alternatives require doing the same interpretation with an ordinary model first, move this early-check candidate aside for that input class. Continue the existing compatibility startup preparation independently. Changed-evidence triage remains a research possibility until it has a concrete consumer, maintained claim-to-source links, and useful rereading work to improve or remove.

The corrected synthesis supports this preparation recommendation; the operator's scope decision remains open. It changes no reliability bar, required review, authority policy, live hook, upstream hold, or execution-acceptance boundary.
