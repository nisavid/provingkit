## Actionable findings

1. **[P1] The initial Git state is not checked before launching the authoring turn.** `E/prepare.py:77–79` and `E/run.py:39–44` exclude every `.git` file from the fixture inventory. The runner never compares current HEAD with the manifest baseline or verifies the effective hook configuration, signing override, index, branch, or remotes. Changing `core.hooksPath` after preparation leaves all checked file digests unchanged and can launch an episode without the passive observer; changing HEAD or the index likewise changes the episode's initial state. The later commit/tree reconciliation cannot make the initial episode match its accepted manifest. Smallest correction: record and compare a semantic Git-state snapshot before native import, including HEAD/baseline, branch, clean index/worktree, no remotes, effective hooks path, and signing setting. Avoid hashing volatile Git files indiscriminately.

2. **[P1] Added resources escape the claimed full skill-tree drift check.** `E/profile.py:105–109` inventories existing files, but `verify_profile` at lines 69–73 only rehashes those recorded paths. Adding a new resource inside a named skill tree passes both pre-turn and post-turn verification; the discovered SKILL.md digest also remains unchanged. The child can consume a new helper or reference while the run reports no profile drift. This conflicts with the bound full-resource-tree claim in `E/contract.md:25–31,69–70`. Smallest correction: persist the named resource-tree roots and compare freshly enumerated relative file sets plus identities at each verification, preserving the stated exclusion for unbound transitive resources.

3. **[P1] The loaded instruction inventory is not reconciled with the native thread.** `E/profile.py:98` binds only CODEX_HOME's AGENTS.md and config.toml; `E/native.py:153–164` ignores the start response's loaded instruction paths. `S/ThreadStartResponse.json:3081–3088` explicitly exposes `instructionSources` as paths currently loaded for the thread. Instructions found through other applicable locations can therefore affect authoring without being represented in the prepared profile, despite the contract's installed-instruction preservation claim. Smallest correction: obtain the effective source list through metadata-only preparation if available, bind its identities, and compare it at thread start before sending the task. If that list cannot be prepared, retain the actual list and refuse or disclose the unsupported profile claim rather than treating the two fixed files as exhaustive.

4. **[P2] Non-tool items consume the forty-tool limit.** `E/native.py:116–122` counts every item except userMessage, agentMessage, and reasoning. The supplied protocol includes `plan`, `subAgentActivity`, and `contextCompaction` as distinct display/history items (`S/ItemCompletedNotification.json:960,1403,1627`). A plan item or child activity notification can therefore advance the tool counter and cause an unnecessary stop before forty actual tool calls. Smallest correction: explicitly enumerate actual tool-call/execution item kinds, count them once by thread and item ID, and retain non-tool observations separately. Alternatively, rename and freeze a general item budget, but that changes the proposed contract.

5. **[P1] Incomplete observer attempts do not disqualify the hook-context classification.** `E/native.py:39–45,50–67` scans only directories containing record.json and marks the boundary matched whenever every final commit has some valid matching record. An observer directory with retained message/patch bytes but no record.json is ignored. An explicit incomplete record is retained as invalid but does not prevent matched when a later repeated attempt supplies the matching tree and parent. That permits matched alongside missing or incomplete invocation evidence, contrary to `E/contract.md:82–88`. Smallest correction: inventory every observation directory, retain missing-record/invalid statuses, and make the hook-context qualification reflect all incomplete attempts. Preserve candidate commit correspondences separately so a later valid record does not erase earlier uncertainty.
