# Select the bounded record window and account for its work

The coordinating agent performs this manual collection procedure with the existing local file tool and Python standard-library file/JSON operations, then invokes the tested importer. It is a workload-specific observation procedure, not an automatic relevance selector or an installed collector. Its first use remains unqualified until the accepted observation records what was actually retrievable. Failed or incomplete collection remains a result.

## Read and select records

1. At acceptance, verify that the privately bound chat and turn still cover the selected ordinary increment. Read its status using the Codex chat tool. Record the acceptance timestamp, the local source's device/inode and byte size, and the last complete line-feed boundary at or before that size. Find that boundary by reading at most the last 1 MiB in memory. If none is found, retain a capture gap and stop collection. Do not classify activity already reported at this point as prospective.
2. For antecedent context, read at most 8 MiB immediately preceding that boundary from the one bound source. Use a binary file handle, seek to the fixed start offset, and read the fixed byte count once. When that start is not zero, discard the leading fragment through the next line feed. Preserve its omitted byte range in the collection record. This may omit older requirements; the initial chat snapshot supplies only the visible selected requests and reports it actually returned. No full-history or complete-intent claim follows.
3. At the terminal snapshot or the observation limit, recheck source device/inode. For prospective records, read from the acceptance-time complete-line boundary to the smaller of the current file size and that boundary plus 8 MiB. Do not rescan the 148 MB history, follow other chats, or widen the bound. If identity changes, the source is unavailable, or the available appended content exceeds the limit, retain an incomplete observation. Ordinary task work continues.
4. Split the bounded in-memory bytes on line feeds, preserving absolute source offsets and original bytes. A final fragment without a line feed is not interpreted or imported; record its omitted offset and length. The first prospective line may straddle the acceptance timestamp because the prior read ended mid-record. Treat it as a boundary-crossing record, not a proved prospective event. Timestamp disagreement or absent timing likewise leaves event placement unknown.
5. Parse complete records in memory. Eligible visible content is `response_item` messages whose role is `user`, or role `assistant` with phase `commentary` or `final_answer`, plus the associated `function_call`, `function_call_output`, `custom_tool_call`, and `custom_tool_call_output` records. Eligible measurement content is `event_msg` records with `token_usage_record`, `item_completed`, `task_started`, `task_complete`, or `turn_aborted` types. Retain only records related to the bound turn or necessary antecedents. Unknown shapes, malformed lines, missing turn attribution, and unjoined call/results are marked as gaps rather than interpreted as equivalent known fields.
6. Exclude internal reasoning, system/developer messages, world-state/config records, and unnecessary private material. Do not retain an eligible wrapper when it contains excluded content. This selection is the coordinator's explicit content review; it is not a claim that a parser can establish permission or relevance. If redaction is necessary, retain a separately identified redacted derivative and omission description; never label transformed bytes as an exact source span.
7. From the eligible records, explicitly select those needed to establish current requests/amendments, the new report, a relevant choice or continuation, associated verification and failures, and available measurement endpoints. Save the selection rationale and exclusions in a local collection record. Construct the import manifest with each selected record's original path, absolute byte offset, length including its line feed, SHA-256, meaningful label, and `jsonl` format. Related task artifacts use `bytes` spans and the same total budget. More than 128 required spans, more than 8 MiB selected bytes, or a partial index limits the result; do not silently choose a larger budget or substitute records.
8. Run the pinned `import_records.py MANIFEST NEW_DIRECTORY` once. Retain its exit status and resulting files. An incomplete import receives no automatic retry. Relate each retained record to the chat snapshot by matching available message/call, turn, and thread identities. A missing identity, truncated tool output, or mismatch remains an explicit gap. Snapshot text is a separately identified projection, not a replacement for missing original record bytes.

The private collection record contains acceptance/start/end boundaries, source descriptors, read ranges, skipped fragments, selected span rationale, omitted record categories/counts where observed, import invocation/result, snapshot identities, and unresolved correspondence. This is observation evidence, not a new standing ledger. A source hash identifies bytes; it cannot establish complete context or semantic relevance.

## Measurement routes and gaps

| Component | Route for this observation | Limit retained in the result |
| --- | --- | --- |
| Source acquisition and import | Tool-reported command duration, collection timestamps, and importer `elapsed_seconds` | Import timing excludes startup/shutdown and final receipt serialization. Tool duration is elapsed time, not active human time. |
| Coordinator selection, interpretation, and reconciliation | Mark the first and last relevant coordinator actions and retain their visible calls/outputs; record any active-time estimate as an estimate | Active reasoning time is unknown without a direct measure; intervals may overlap waiting and other work. Do not report elapsed intervals as active time. |
| Observed agent attempts and usage | Join retained token-usage records by available response, turn, and thread identities; keep raw input/cache/output/reasoning counters and endpoint scope | Preserve raw observations before aggregation. Missing attempts, ambiguous cumulative/delta semantics, unavailable child usage, and failed-attempt usage remain unknown. Do not add overlapping endpoint totals. |
| Cache reuse | Retain cache counts and any source-visible scope on the corresponding usage records | Cached tokens do not establish avoided work, quota savings, actual pricing, or provider execution. |
| Downstream checking, retrieval, and recovery | Relevant visible calls/results, subsequent ordinary report, and available task artifacts | Off-record actions, nested-operation duration, unretained failures, and historical setup costs remain unknown. |
| Operator checking or resumption | The brief voluntary record of work done anyway | Estimates and recall uncertainty remain labeled; absence of a record is unknown effort. No exercise is requested. |
| Measurement burden | Same voluntary record for operator logging; coordinator actions and importer timing for collection | Interpretation/setup costs not directly measured remain estimates or unknown, not zero. |
| Ambient assessments and shared accounts | Retain relevant observed assessment/call records if present in the selected source | Absence from the selected window does not prove absence. Other-chat usage, account quota consumption, billing, and actual effective model execution remain unknown. |

The result keeps research/setup, recurring workflow work, and this observation's measurement overhead separate. Every value carries a source pointer and a measured/estimated/unknown label. Shared acquisition is charged once for combined use; standalone and marginal work are listed without claiming that descriptive observations demonstrate savings.
