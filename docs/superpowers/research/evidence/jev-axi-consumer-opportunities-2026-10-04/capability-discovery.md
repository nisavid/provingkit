## Proposal 1: orientation for an unfamiliar repository task

**Consumer and decision:** an agent implementing an ordinary repository change chooses how to locate relevant code. A concrete proposed sequence is: receive “add a JSON flag to the list command”; inspect repository instructions and paths; choose deterministic search, ordinary reading, or a relevant advertised command; retrieve detailed flags only if needed. This is an observation proposal, not a retained native sequence.

**Predicted benefit:** fewer broad help/catalog reads or unrelated context, while selecting an equally useful path. Establish which orientation actions actually occur before claiming replacement. An already-known command may make omission best.

**Decision-time inputs and producers:** current task/amendments from the native conversation; repository instructions and tree from ordinary inspection; source-pinned command names/descriptions and help from existing source. A compact recurring reference would need a producer to select and maintain its contents; on-demand retrieval incurs lookup and reading. Neither producer is free.

**Comparators:** ordinary harness discovery; deterministic command-name/task-term lookup and repository search; compact recurring command reference; detailed reference retrieved at the first relevant decision; omission of the added reference, retaining ordinary work. Source-generated full status remains the existing integration comparator, with its actual side effects and context included.

**Jev boundary:** initially none. Only if explicit names, task terms, and ordinary reasoning leave consequential ambiguity, consider selecting among a supplied small command menu, including ordinary search and abstention. Jev cannot discover absent commands or prove readiness. Menu construction, context preparation, judgment, and downstream work must be charged separately.

**Contrasts:** unfamiliar semantic task versus an explicit command request; one known file versus an unknown subtree; relevant command versus irrelevant task; amended task versus obsolete description; complete versus missing help. Include ordinary unaided successes.

**Defeat:** retrieval or reference maintenance costs exceed avoided orientation, advice steers toward an inferior command, or task quality declines. The cheapest informative next observation is one ordinary task's first code-location decision with exact visible context, discovery actions, selected path, and final result retained. It would locate a comparison opportunity, not qualify benefit.

## Proposal 2: availability information at the moment of use

**Consumer and decision:** the same agent, after finding a potentially relevant command, decides whether to use it or continue ordinary work.

**Predicted benefit:** avoid repeated configuration/help investigation or a fruitless attempted call. No such repeated work is established in the supplied evidence.

**Inputs and producer cost:** installed command/dependency identity, metadata timestamp, supported route, and operation-specific readiness evidence supplied through a separately accepted observation. Source/configuration labels alone cannot supply those premises. Count permitted probes, failures, refreshes, and attention; do not silently replace status with a free live readiness service.

**Comparators:** ordinary discovery/error handling; deterministic freshness and evidence-presence rules; compact recurring labels; on-demand evidence retrieval; omission of extra labels. Jev has no demonstrated residual judgment here.

**Contrasts:** ready versus unavailable; fresh versus stale label; key-present but unavailable versus usable route; missing credentials; repeated starts; task context arriving after startup. Missing readiness evidence means unknown, with the ordinary fallback retained.

**Defeat and next observation:** extra probes duplicate ordinary handling, stale information misleads, or avoided attempts cost less than refresh. Cheapest next step: retain one ordinary decision's available metadata, attempted/skipped action, observed outcome, and handling cost; do not manufacture failure to claim prevention.
