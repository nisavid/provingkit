# Critique of the exploratory workflow hypotheses

**Concrete corrections**

**The catalog presumes each hook deserves a job.** It is organized by hook family, and every family receives an opportunity. That is the presumption the brief warns against. The fix is to index by need (assurance, continuity, allocation, discovery, repair) and treat "no event fits" and "this hook gets no job" as explicit outcomes. Several better placements are not current catalog events: task-change detection, first relevant use, handoff detection, commit preparation, and task completion. Others are absent entirely, such as prompt submission and context compaction, if the installed harness exposes them. If jev-axi must synthesize a missing event, that synthesis is itself a judgment with its own cost and error rate.

**Several proposals assign generation to Jev.** Each of these asks for content, not a typed verdict on supplied inputs:
- the commit-msg outline,
- the PostToolUse "suggest a different observation,"
- the pre-commit "identify a consequential semantic question,"
- handoff composition,
- the environment-repair suggestions.

Recast each so that Jev returns a bounded type, with abstention, over supplied evidence. Examples:
- "is another similar attempt likely redundant: yes/no/unsupported"
- "does this claim's cited evidence concern this requirement and revision"
- "is this response a completion, pause, or decision request"

Generation belongs to the acting agent or to jev-axi.

**Jev's role in verification needs tightening.** Stop #1 says "sufficient, applicable evidence, including tests where required." Jev cannot establish that tests ran, passed, or exercised the criterion. Deterministic checks must supply that. Jev judges only the fit between claim and evidence. Source 3 states this boundary; the design input should too.

**The requirement-revision record is unacknowledged.** Stop, PreToolUse, pre-commit, and pre-push all consume "current request and amendments." Nobody owns constructing it. Extracting requirements is expensive and error-prone, and its errors propagate everywhere. It needs its own owner, cost line, and acceptance bar, or it will silently erase downstream gains.

**Integration-only wins can be credited to Jev.** Capability maps, cadence gating, cache invalidation, and deterministic dispatch are jev-axi value. Accounting should attribute each effect so that a jev-axi win is not counted as Jev qualification.

**Consumers are always agents.** On successful tasks, a plausible useful result is reducing the operator's verification effort, for example with a typed claim-to-evidence map. That requires the operator as a named consumer, a separate bar, and operator effort charged in the account. It must not manufacture questions.

**Cost lines are missing:**
- synchronous latency on per-call hooks, especially PreToolUse;
- attention displacement in the acting agent;
- possible prompt-cache disruption from mid-session context injection (unverified here);
- rework induced by false discrepancies;
- maintenance of deterministic mappings;
- the qualification portfolio itself. Thirteen-plus hypotheses each needing a frozen contract is a real expense.

**Cheap observations carry selection and hindsight bias.** "Inspect one existing case" and "first point the discrepancy was knowable" are both biased. Pair each with three things:
- the frequency of the condition across retained records,
- how often ordinary behavior resolved it unaided,
- annotation done without knowledge of the outcome where feasible.

The missing original Stop records further limit base rates.

**Each new purpose needs its own concrete bar, not just "separate claims":**
- **Continuity:** measured rediscovery after resumption, with no omitted consequential uncertainty.
- **Routing:** skipped reviews show no quality loss on critical cases.
- **Authoring support:** message accuracy no worse, with deliberation removed.

**Strongest research leads**

**1. Claim-to-evidence reconciliation at a completion claim (Stop #1 + source 2).** This extends an accepted purpose rather than replacing it. Deterministic checks handle record presence and revision agreement, and Jev handles only a narrow mismatch judgment, which fits a typed service. The record could be reused by pre-push and possibly by the operator, giving value on successful tasks. Its viability depends on the requirement record.

**2. Event-meaning classification and evidence-change cadence (sources 1 and 3).** This targets model calls already being made, so it is the clearest route to *removed* work rather than speculative addition. It reduces false interventions on legitimate pauses and is cheap to observe in retained records. Much of it may be deterministic native state, which is fine. It would then qualify jev-axi, not Jev.

**3. Continuity at handoff or compaction (Stop #3, re-placed).** Rediscovery after resumption is directly observable, and compaction is a forced handoff that occurs on successful tasks too. Expect this to be mostly integration work. Jev earns a role only if selecting which uncertainties matter proves ambiguous.

**Deprioritize** commit-msg authoring (generative, late), PostToolUse alternative suggestion (generative), and PreToolUse scope reconciliation (per-call latency and proximity to the excluded security work). SessionStart shortlists should wait until native deferred discovery and library size are checked; source 4 reports weak value for small libraries.

**Cheap distinguishing observations**

- Check whether retained Stop inputs contained the final response and any in-flight work indicators. This tests input integrity before testing judgment.
- Label retained supervision calls by whether new decision-relevant evidence appeared since the previous call. This estimates removable calls directly.
- For retained completion claims, count how often the cited evidence matches the requirement and revision under deterministic checks alone. The residual is Jev's maximum addressable share.
- Count how often requirement amendments occurred and whether any retained record could reconstruct them. This tests whether the ledger is buildable.
- In resumption pairs, count repeated tool calls and re-read files attributable to missing handoff facts.
- In the evidence used for an observation, record whether an existing blanket review could have been skipped. If there is none, routing has nothing to remove.

**Unresolved user decisions**

- Whether the operator may be a named consumer.
- Whether events outside the current catalog (prompt submission, compaction, task completion, synthesized handoff) are in scope.
- Whether jev-axi may be retained on integration-only wins independent of Jev.
- Who owns the requirement-revision record, and whether it is in scope at all.
- Whether "no review needed" is a permitted output, which implies authority to omit work.
- How many hypotheses receive observation contracts given portfolio cost.
- Whether model upgrades trigger mandatory requalification of retained or removed placements.

These are recommendations for consideration, not decisions. The cited sources were taken as supplied and were not independently verified.
