# Observe ordinary commit-message authoring

This passive observation establishes what a Codex developer episode actually
does before a local commit: writing the message, any separately observable
review, the message and staged changes available to a hook, and observable
costs. It selects no behavior assignment and makes no Jev request.

The [accepted family purposes and bars](../../2026-10-02-jev-axi-remaining-family-acceptance.md)
govern later comparisons. The [preparation findings](../../2026-10-02-jev-axi-commit-message-preparation.md)
leave a separately replaceable review step unverified. This observation neither
prescribes an extra semantic review nor injects a misleading message. No defect,
no separate review opportunity, or an unavailable native capability is a valid
finding. Do not automatically expand the workload or start judgment trials.

## Input and authoring profile

Run one fresh Codex CLI episode on the [report sorting task](prompt.md), using
the retained standard-library report application as its seed. The task includes
implementation, CLI tests, documentation, and a local commit. Its test boundary
is stated in the prompt. The repository has no remote, no DCO requirement, and
an explicit keep-local outcome. Preparation uses the host Git identity, disables
signing only in the fixture, and installs only the passive commit-msg observer
there. The prepared repository remains available after the run.

Preserve the installed global authoring instructions, skill discovery, plugins,
and native review delegation. Record all discovered skill entrypoints and the
full resource trees of the named checkpointing, TDD, writing, procedure-capture,
review, critic, and delegation skills, excluding bytecode caches. Other transitive skill resources are
unbound; using them limits claims about the profile. The [metadata-only inventory](profile-evidence.json)
observed Codex CLI 0.160.0 and 179 skill entries. Native discovery must match the
prepared inventory before the task prompt is sent. Preparation binds the installed
global instruction file and config, but creates no native thread. Its expected
loaded instruction-source list is a hypothesis: the controller retains and
checks the thread-start source list and refuses a different or unavailable list
before task delivery.

Select GPT-6.1 Sol at medium effort for the parent. The prompt permits at most
two native child dispatches on the same model at high or lower effort, without
nested delegation or another harness. The invocation sets two concurrent slots
including the parent, and defaults children to Sol at high effort. The prompt
limit and observed-dispatch guard are not a provider request budget. The current
[Codex source](https://github.com/openai/codex/blob/main/tui/src/debug_config.rs)
says `max_depth` does not bound V2 recursion; this contract
does not rely on it. Child histories and available usage stay separate from the
parent until their accounting semantics are reconciled.

Per-invocation overrides disable native hooks, plugin hooks, memory, apps,
browser/computer tools, and image generation; disable all inherited MCP servers;
and disable shell snapshots and web search. This removes more ambient features
than the disputed assessment. Conclusions apply to this disclosed authoring
profile, not the full desktop installation. The task forbids external services,
installation, Jev and jev-axi calls, and live configuration changes. Source
reading of installed skills remains available. No live settings are edited.

Use native workspace-write permissions, no tool network access, and no extra
writable roots or shared temporary-directory access. Native permission and
user-input requests stop the run and are retained unanswered. The controller
does not approve, deny, or work around them. These are configured boundaries for
an ordinary cooperative task; this observation does not qualify adversarial
containment or a new permission policy.

## Execution and stopping

Preparation and local tests are authorized. Native task execution waits for
acceptance of the reviewed, published source and concrete manifest digest.
The manifest's `execution_authorized: false` records that preparation itself
grants no authority; the later operator answer supplies execution authority.

The parent starts one task turn. The native-process deadline is 480 seconds;
transport shutdown can add up to ten seconds. There is no automatic retry,
separate smoke, task amendment, or model fallback. Preserve all attempts,
including preparation failures. Once valid arguments and a writable scratch
parent are available, preparation creates a receipt before fixture effects and
records the partial root on failure. The coordinator retains command output for
argument errors, unavailable receipt storage, or abrupt process loss. The controller retains up to 2 MiB of combined
process output, then stops with the retained prefix marked incomplete. It stops
on an observed count above 40 distinct tool calls or two child dispatches, unexpected
hook delivery, changed source/profile, a native request requiring human input,
or incomplete native history. These observed limits can detect an operation
after it has begun; they are not preauthorization controls or token caps.

The run command checks the supplied manifest digest, runtime source, and initial
fixture, including semantic Git state, before importing native execution. It reserves the episode once and
rejects existing episode records. Each valid run invocation with usable receipt storage has a distinct launch receipt.
The native controller checks version, model capability, authoring inventory,
disabled connectors, effective thread/turn permissions, and exact task delivery.
Recheck Git state immediately before prompt delivery. Retain root and child
histories and available usage endpoints when the protocol supplies them. After
native shutdown, attempt final Git and observer capture on success and failure,
with a ten-second capture deadline and at most twenty commits. Record capture
failure separately without replacing the primary interruption. Incomplete
native histories remain unqualified.

The Git observer records the message bytes, staged binary patch, index tree,
parent commit, and timestamp on each invocation. It neither judges nor rewrites
the message and emits no steering. Recording failure leaves the commit alone;
missing, incomplete, or unmatched records disqualify hook-context claims. A
matched tree and parent establish a candidate correspondence, not unique
message identity after Git cleanup or repeated attempts. Review those cases
using the retained raw messages and final commit messages.

## Grading and accounting join

After the accepted run, independent outcome/context and accounting reviews join
before the observation is reported. The first checks the final change against
the ordinary task, distinguishes materially misleading messages from concise
accurate ones, and separates drafting, observable review, and unknown internal
reasoning. A missing tool call does not prove that review was absent. Count
permission stops, questions, failed tasks, and missing commit opportunities.
No safety or adversarial efficacy is measured.

The accounting review retains setup, metadata discovery, local testing, native
parent and child attempts, source/profile refresh, review, interruptions, and
recovery separately. Report provider token fields and cache/reasoning details
only with their observed meanings. Do not sum parent and child totals until
their overlap and cumulative endpoints are established. Unavailable child
usage, isolated review cost, operator time, quota consumption, or money remains
unknown. Setup is a research cost; no amortization assumption or general savings
claim follows from one episode.
