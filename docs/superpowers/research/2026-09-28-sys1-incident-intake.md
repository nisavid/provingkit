# Sys1 incident intake procedure

`handling-sys1-incidents` is a reusable intake aid for an observed Sys1 denial, supervision misdirection, repeated intervention after approval, or unexpected service failure. It guides an investigator to preserve the action and authority record, separate each occurrence from its case and accountable owner, distinguish witness reports from runtime observations, test competing explanations, and hand back the smallest supported correction or an explicit unknown. It keeps safety and task alignment as separate outcomes. Publication of this procedure is accepted with the limits below; it does not qualify autonomous incident adjudication or a runtime correction.

The maintained source is [the skill](../../../.agents/skills/handling-sys1-incidents/SKILL.md), with an [evidence record](../../../.agents/skills/handling-sys1-incidents/references/evidence-record.md) and [comparison contract](../../../.agents/skills/handling-sys1-incidents/references/comparison-contract.md). `AGENTS.md` tells agents when to invoke it. The `.claude/skills/handling-sys1-incidents/` projection matches the three source files byte for byte. Consumers should load the reviewed source revision, record it in the handback, and use `adopting-jev` when work reaches Jev integration design. Ordinary tool failures, pending permission requests, and general adoption remain outside this incident procedure.

The current instruction distinguishes information not retained (`unknown`), information outside the allowed read boundary (`inaccessible`), and fields with no role in the occurrence (`not applicable`).
