## Access, lifecycle, and operating costs

The confirmed getters are methods on the **already owned query object**, not a passive external attachment API. `query()` in the bundled wrapper constructs a new query instance; direct connect starts a session transport, and `reinitialize()` sends initialization again. Bundled SDK `[1097300,1098200)`, `[1104950,1105600)`, `[658000,659200)`, `[1072000,1072400)`. A Desktop caller must obtain its existing selected record/query/stream through an authorized app route; a renderer IPC caller remains renderer-bound, and an owning-task MCP tool would add task/conversation activity. The Manager singleton exists in this archive, but source injection/load/selected caller behavior is not yet a supported route merely because the singleton can be imported. Manager `[1595500,1596495)`.

Each getter writes a control request, creates a pending handler, and can acquire a whole settings/rules/status response before an observer filters output. A promise deadline alone does not cancel the request; an internal abort can write a cancel frame. Bundled SDK `[1069850,1071900)`. Manager's request accounting helper returns the original promise even if the record's query later changes, so a late reply must remain old-query evidence rather than satisfy a replacement sample. Manager `[530850,531800)`. Teardown closes/clears the query and stream, increments `promptEpoch`, and clears many pending caches. Manager `[1037400,1043600)`. The eventual collector needs independently selected task and actual executor witnesses, captured query/stream references, before/after binding checks around each asynchronous request, and separate acquisition intervals. It cannot claim atomicity or preserved pre-restart identity.

The worktree getter itself is non-resolving after owner initialization, but it internally clones/scans the full registry and may be reached through a cold owner with persistence/error effects. A finite Desktop adapter would add a loader guard, task admission, timers/files or other result transport, bounded fallback tap, request/response handling, retention, cleanup, and compatibility maintenance. Startup loading changes the query lifecycle and needs an independently rebound candidate task; an ordinary-app restart interrupts current work and cannot preserve the former query object. A new Engine diagnostic would additionally need canonical source, build, protocol/SDK/Manager wiring, state-lifecycle coverage, installation and restoration. Neither compiled archive inspection nor a public repository without source establishes that path. Candidate results require an explicit comparison and an ordinary-build check before transfer; restored bytes do not prove restored running behavior.
