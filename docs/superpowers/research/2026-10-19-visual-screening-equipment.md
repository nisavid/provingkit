## Procedure-capture proposal

**Proposed trigger:** an agent needs a repeatable visual check whose supported claim survives a deterministic-first assessment.

**Proposed maintained source:** let the visual-screening map reconcile the capture/screening procedure with existing browser equipment and the Provingkit orchestrator. Keep consumer rubrics with their app/component owners; reuse Agentworks’ result seam and Formgiving’s presentation contract where applicable. No installed convention or new plugin is selected here.

The procedure should:

1. Bind the claim, consumer, current authority, supported state, and evidence required beyond pixels.
2. Select deterministic/specialized checks first; state why screenshot judgment remains necessary.
3. Validate bytes against declared format; record source/state, dimensions, viewport, scale, crop, masks, and redaction transformations with original/derived identities.
4. Bind rubric, question, provider/model/configuration, reference labels, and input-use permission separately.
5. Preserve per-criterion raw outputs, interpretation, errors, unavailable inputs, disagreement, and referral; never turn missing evidence into pass.
6. Return evidence links and an advisory result to the existing reviewer. Publish only authorized public projections.
7. Invalidate affected evidence when candidate, rubric, capture, model, or relevant dependencies change.

Acceptance should include discovery and application cases, malformed/unsupported inputs, stale evidence, failure and referral behavior, independent review, source publication, targeted installation where separately authorized, and downstream invocation tied to the reviewed revision. This is a capture proposal under `capturing-agent-procedures`, not a completed procedure delivery.

The maintained [Sys1 comparison contract](https://github.com/nisavid/provingkit/blob/fc50152d2d53cf9b50db4202d1c4506765d65fa4/.agents/skills/handling-sys1-incidents/references/comparison-contract.md) supplies the comparison boundary: ordinary work, omission, meaningful deterministic/specialized alternatives, and the candidate; capture through preparation, calls, review, referrals, failure, recovery, and maintenance; separate tokens, rate estimates, actual charges, capacity, latency, and operator effort.
