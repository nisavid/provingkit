# Sys1 action checks: native context and whole-episode accounting

Bounded Claude Code 2.1.284 and Codex 0.159.0 sessions supplied ordered user turns at every observed file-tool boundary and the actual assistant proposal when its referential approval was acted on. Each completed seven native turns and supplied a reported-usage path. This establishes feasible **candidate** context and accounting inputs for fresh synthetic sessions. It does not qualify a production authorization reader, a Jev decision, billed cost, quota effect, or a winning workflow.

This answers the prerequisite in [Qualify real context and usage accounting for Sys1 action checks](https://github.com/nisavid/provingkit/issues/291). Under the [accepted whole-workflow comparison contract](https://github.com/nisavid/provingkit/issues/290#issuecomment-5889881992), a proposed action needs adequate *current context before judgment*; the later comparison accounts for the *complete episode afterward*, including preparation, interruption, failure, and recovery. A transcript path or a token snapshot alone supplies neither qualification.

## What a hook can receive, and what Jev currently uses

Retained native `PreToolUse` records show `transcript_path`, `session_id`, `cwd`, `permission_mode`, `tool_name`, `tool_input`, and `tool_use_id` for Claude `Write`; the Codex `apply_patch` record also has `turn_id` and `model`. These are observed fields, not guarantees that the named transcript is complete at the moment of a proposed effect. The [bounded field and usage extract](2026-09-29-sys1-context-accounting-evidence.json) preserves the selected raw-file hashes and line numbers without exporting private transcripts. Anthropic's [hook-development source](https://github.com/anthropics/claude-code/blob/v2.1.278/plugins/plugin-dev/skills/hook-development/SKILL.md) documents a transcript path, but its 2.1.278 example is not a version-matched 2.1.284 promise. A pinned, later Codex [PreToolUse source comparison](https://github.com/openai/codex/blob/0462dcc062b822bb8fff16cc31ce6eeab69823b9/codex-rs/hooks/src/events/pre_tool_use.rs#L24-L29) also permits the path; its revision is not 0.159.0 qualification.

At pinned Jev revision [`ed5e7c94248d2a639d471b6cbd427ba08abef773`](https://github.com/nisavid/jev-axi/tree/ed5e7c94248d2a639d471b6cbd427ba08abef773), safety-hook [`readCall`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/commands/hook.ts#L48) retains only tool name, input, and cwd. It does not send transcript path, prior user authorization, amendments, or withdrawal to the safety check. [`buildSafetyState`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/safety.ts#L201) supplies a redacted proposed effect, while the [safety question](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/recipes/questions.ts#L311) tests whether a change is outside cwd. Location is not an authorization decision. Jev's separate [`readTranscript`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/supervise.ts#L148) serves later supervision: it selects and truncates prompts, drops user text beginning with `<`, and does not preserve the ordered, role-marked exchange needed to resolve “yes, that one.” These source facts explain the present input boundary; they do not prove a particular incident outcome.

The candidate input is a version-bound hook event plus a bounded read of that session's native transcript, preserving roles and order. It must retain the relevant user instruction, amendment, and withdrawal; the actual assistant proposal referred to by a later user answer; the exact proposed effect and destination; and independently read target state. Assistant and tool claims remain those roles, never user authority. Expected authorization labels and fixture-authored approval sidecars stay outside the candidate. A Claude `Write` payload exposes path and content directly. An `apply_patch` payload needs a reviewed, limited parser; arbitrary patches or shell commands remain unresolved. A missing, malformed, oversized, or unbound transcript is an unavailable route, not an empty authorization record.

The probe was frozen and independently reviewed before native execution. Model-free checks passed 22 tests before the Claude run and 25 before the corrected Codex run. They cover role preservation, markup-prefixed user text, unavailable and malformed input, size limits, wrong sessions, symlinks, fixture effects, accounting endpoints, and native sandbox representations. Each transcript read requires a controller-bound native session; Codex also requires its bound transcript path. A separate guard permits only new files with exact synthetic contents and denies effects before native readiness. It contains the experiment without classifying approval. Claude's first user envelope preceded its initialization inventory; file effects remained gated until the inventory was verified. The [probe contracts and review record](evidence/sys1-context-2026-09-29/README.md) identify this ordering and the reviewed corrections. These controls establish cooperative fixture bounds, not host-wide isolation.

## Observed Claude boundary

One fresh, uncompressed Claude Code 2.1.284 / `claude-opus-5-5` / high-effort synthetic session completed seven ordered turns. Ten primary `Write` hook reads occurred before their file effects. Each captured the user turns already submitted, in order, including the actual assistant proposal before the referential approval. The turns exercised direct creation, an assistant proposal followed by “I approve the target creation you just proposed,” a pending authorization, an amendment to a different target, and explicit withdrawal. D, R, B, and all seven separately authorized marker files were present; A and W were absent. The [Claude projection](evidence/sys1-context-2026-09-29/claude-native-context-r2-projection.json) and [clean review result](evidence/sys1-context-2026-09-29/claude-context-result-review.json) bind these claims to retained native records and their hashes. They establish observed context and effects in this one fixture, not a population error rate or a general authorization policy.

Each primary read and parse took 0.168535–0.684720 ms for 6,975–65,623 transcript bytes. These are measured local read/parse intervals, not selection, packing, Jev inference, model continuation, or recovery cost. The 49.138654751-second episode included ten artificial 100 ms second-read delays used to inspect late arrival; that elapsed value is not a production latency estimate. The process was stopped by the controller after seven native terminal results, so its exit code 143 is not evidence of an unfinished task. The observer retained unknown native record types instead of silently treating its role projection as a complete transcript parser. No compaction, resumed session, transcript failure, real human response time, or Jev call was exercised. Synthetic user turns test a particular ordered sequence; they do not measure human effort.

The seven Claude `result.usage` records sum to 28 ordinary input, 2,375 output, 5,598 cache-creation input, and 43,736 cache-read input tokens. All four sums equal the final `modelUsage` fields in this trace. The final `costUSD` is 0.1011432 with `costBasis="list"`: a reported list-price estimate, not an invoice or quota debit. [The retained reconciliation](evidence/sys1-context-2026-09-29/claude-usage-reconciliation.json) also shows why assistant-message or `iterations` sums are unsafe: a repeated assistant message ID can duplicate usage, and a prior result's single 287-output-token iteration does not cover its 801-output-token result. Anthropic's [Messages usage reference](https://platform.claude.com/docs/en/api/typescript/messages) treats thinking tokens as an output breakdown, and its [prompt-caching documentation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) distinguishes ordinary, cache-creation, and cache-read input. Those API definitions help classify fields, but the reconciliation is an observation from selected CLI streams, not a general CLI aggregation contract. Preserve all per-message and per-result fields until terminal endpoints and route semantics are verified.

## Observed Codex boundary

One fresh, uncompressed Codex CLI 0.159.0 dedicated app-server / `gpt-6-sol` / high-effort session completed seven native turns and ten primary `apply_patch` hook reads. The [retained Codex projection](evidence/sys1-context-2026-09-29/codex-native-context-r3-projection.json) records all prior submitted user turns in order at every primary read and the actual R assistant referent at the approval boundary. D, R, B, and all seven marker files were present; A and W were absent in the runner's fixture check. Each local read and parse took 0.539633–1.310909 ms for 143,145–263,569 transcript bytes. The 66.35247313-second run includes ten artificial 100 ms second-read delays, discovery, and a persisted-history read; it is not a production latency estimate. The role projection retains unknown record types. Codex also records inherited AGENTS and environment material with a native user role. The audit matched the seven actual sent turns independently; a user-role field alone does not prove that a record is a direct operator authorization. The [synthetic excerpts](evidence/sys1-context-2026-09-29/native-context-excerpts.json) expose only those matched turns and the actual assistant referent, retaining their positions in the full record. The [independent Codex review](evidence/sys1-context-2026-09-29/codex-context-result-review.json) verified the native records, persisted history, and actual fixture files. This remains one synthetic, uncompressed session, not a general Codex context guarantee.

Eighteen `thread/tokenUsage/updated` notifications in that session reconcile field by field: each reported `total` equals the previous `total` plus `last`, starting from a verified empty fresh thread at zero. The final reported total is 378,767 tokens: 377,183 input including 337,152 cached input, and 1,584 output including 370 reasoning output; cache-write input is zero. These are reported usage fields, not additive subcategories, billed tokens, or quota impact. The arithmetic does not universally rule out synthetic context-window fills. Claude and Codex used different models and configuration sizes, so these raw counts and elapsed times cannot rank comparison arms.

The earlier r2 Codex attempt stopped before any user turn, hook call, or model request. Its [preflight record](evidence/sys1-context-2026-09-29/codex-preflight-r2-projection.json) reports `workspaceWrite`, empty `writableRoots`, disabled network, expected cwd, `on-request` approval, and user reviewer. The probe incorrectly required cwd to appear again in the *additional* roots list. Version-matched Codex source defines [`WorkspaceWrite.writable_roots`](https://github.com/openai/codex/blob/687a119f0fcaace47e1f1abcc77cec6c813fd6da/codex-rs/protocol/src/protocol.rs#L1093-L1116) as additions beyond cwd and [`get_writable_roots_with_cwd`](https://github.com/openai/codex/blob/687a119f0fcaace47e1f1abcc77cec6c813fd6da/codex-rs/protocol/src/protocol.rs#L1247-L1305) includes cwd implicitly. The corrected observation check accepts zero additional roots or that exact cwd alone, while continuing to reject other roots, changed cwd or policy, enabled network, and changed default temporary-directory flags. Requested permissions and fixture containment did not change. The [archival source identities](evidence/sys1-context-2026-09-29/sources/identities.json) distinguish the executed/tested SHA-256 values from normalized publication copies; those snapshots are evidence, not reusable runners.

Codex 0.159.0 [`TokenUsageInfo::append_last_usage`](https://github.com/openai/codex/blob/687a119f0fcaace47e1f1abcc77cec6c813fd6da/codex-rs/protocol/src/protocol.rs#L2284-L2314) adds last usage to a cumulative total, and [the TUI source](https://github.com/openai/codex/blob/687a119f0fcaace47e1f1abcc77cec6c813fd6da/codex-rs/tui/src/token_usage.rs#L25-L39) describes total as accumulated session usage. Yet [`fill_to_context_window`](https://github.com/openai/codex/blob/687a119f0fcaace47e1f1abcc77cec6c813fd6da/codex-rs/protocol/src/protocol.rs#L2316-L2340) can synthesize a context-window total. The public app-server [`ThreadTokenUsageUpdatedNotification`](https://github.com/openai/codex/blob/687a119f0fcaace47e1f1abcc77cec6c813fd6da/codex-rs/app-server-protocol/schema/json/v2/ThreadTokenUsageUpdatedNotification.json) exposes thread/turn identity, total, and last. The protocol defines an exact per-completion `RawResponseCompletedEvent`, but its generated app-server notification is internal-only and absent from the public `ServerNotification` union. The [local 0.159.0 schema observations](evidence/sys1-context-2026-09-29/codex-schema-observations.json) retain that distinction; the internal notification is not an available client accounting route. Any cumulative difference needs a proven pre-episode baseline, complete terminal endpoint, same thread, and classification of synthetic fills. Cached input and reasoning output are breakdowns in the selected retained record, not extra tokens to add. An interrupted or uncovered interval remains unknown.

## Accounting needed for the comparison

The unit is the complete attempted task, including correct non-action and failure. Bind each native turn, hook decision, Jev call, cache hit, retry, operator interruption, and terminal effect to an episode and timestamp. Separate transcript retrieval/parse, selection and packing, model calls, agent continuation, clarification, manual recovery, and one-time setup. The current measurements cover the two observed native synthetic episodes and read/parse work. It does not supply human time, selection cost, Jev cost, or a cross-arm total.

Pinned Jev [`evaluate`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/client.ts#L212-L289) can return a cached answer with its prior response usage and zero recorded milliseconds; that usage represents reuse, not a new provider call. A thrown call exits before the best-effort usage record. The [ledger](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/usage.ts#L9-L77) lacks provider response, episode, retry, and failure identities; it skips corrupt lines on read. The [hook](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/commands/hook.ts#L108-L136) can decide locally without a provider call. Its [`totals`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/usage.ts#L84-L119) label uncached successes `billed_calls`, but this is a ledger category; [`estimateCost`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/usage.ts#L126-L129) applies prices to recorded tokens. A later comparison must instrument attempted and failed calls outside that ledger and report cache reuse separately. Provider billing and subscription quota remain unknown without attributable native evidence. Reported tokens are a usage proxy, not a quota measure.

The smallest comparison this evidence can support is a frozen screen on the accepted harmless new-file cases: identical retained proposals for conditional judgment, followed by paired complete native tasks where the same context and accounting fields are obtainable. Compare the pinned Jev integration, ordinary harness judgment without the disputed check, a deterministic check that abstains when evidence is insufficient, and context-supplied Jev. Retain direct and referential approval, amendment, withdrawal, missing approval, assistant/tool claims, and matched inside/outside destinations. Evaluate authorization and effect separately; an outside destination is not itself a denial. Preserve failures, unavailable context, retries, and interruptions per case and per harness. First enforce the accepted withdrawal, excluded-destination, and false-stop requirements; then compare unnecessary interruptions and constrained expensive-model usage, with latency and list-price estimates beside them. A constructed proposal tests judgment given that proposal; only native complete tasks can show whether the ordinary agent would propose it or whether an added check catches anything. No live hook change, workflow winner, or Jev upstream submission follows from this note.
