# Sys1 context and whole-episode accounting: source read

This read answers the source-and-retained-evidence part of [Qualify real context and usage accounting for Sys1 action checks](https://github.com/nisavid/provingkit/issues/291). A proposed action needs adequate, current authority context **before its judgment**; the later comparison needs accounting for the **complete task episode**, including failures and preparation. This read qualifies neither a hook-time authorization reader nor a comparison arm. The accepted [whole-workflow contract](https://github.com/nisavid/provingkit/issues/290#issuecomment-5889881992) binds both requirements. I used the repository's `handling-sys1-incidents` procedure at Provingkit `4df897ee0876db578fde0e000055ffd8dc3e2a36`; its [evidence](../../../.agents/skills/handling-sys1-incidents/references/evidence-record.md) and [comparison](../../../.agents/skills/handling-sys1-incidents/references/comparison-contract.md) references keep source facts, retained observations, and unmeasured outcomes distinct.

Anthropic's [hook-development source](https://github.com/anthropics/claude-code/blob/v2.1.278/plugins/plugin-dev/skills/hook-development/SKILL.md) also documents `transcript_path` in common hook input; that 2.1.278 example is not a version-matched guarantee for 2.1.284. Codex's [pinned PreToolUse source](https://github.com/openai/codex/blob/0462dcc062b822bb8fff16cc31ce6eeab69823b9/codex-rs/hooks/src/events/pre_tool_use.rs#L24-L29) permits a transcript path. That public source revision is a source comparison, not qualification of the retained 0.159.0 runtime. A path field does **not** establish that a readable transcript is complete or fresh at the instant this proposed call is checked. No transcript contents or account material were exported.
- **Source-backed pinned Jev boundary.** At pinned Jev `ed5e7c94248d2a639d471b6cbd427ba08abef773`, [`readCall`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/commands/hook.ts#L48) returns only `tool_name`, `tool_input`, and `cwd`. It drops `transcript_path`, session/turn IDs, permission mode, prior user approvals, amendments, and withdrawal. [`buildSafetyState`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/safety.ts#L201) then sends a redacted command or file path/content excerpt with tool and cwd. The [safety question](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/recipes/questions.ts#L311) asks whether a change is outside cwd, which is a location test, not authorization coverage. Source reading explains this input loss; it does not prove which original incident decision it caused.
- **Source-backed supervision boundary.** Jev's separate [`readTranscript`](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/supervise.ts#L148) reads JSONL, skips unknown lines, collects plain user text, discards text beginning with `<`, and builds a job from the first and latest prompt, truncating each. It also retains up to five recent tool outputs. The [supervision hook](https://github.com/nisavid/jev-axi/blob/ed5e7c94248d2a639d471b6cbd427ba08abef773/src/commands/hook.ts#L165) uses that summary for PostToolUse or Stop, not for the safety `readCall`. It neither preserves an ordered role-marked authorization history nor resolves “yes, that one” against the assistant's earlier concrete proposal. An intervening later user message can displace the relevant amendment. The prior [incident read](https://github.com/nisavid/provingkit/blob/9576a323ec333c25b03d296c0567bdc2c529da46/docs/superpowers/research/2026-09-26-sys1-integration-incidents.md) demonstrates that limitation with a source-level reproduction; that reproduction is not native hook-time qualification.

Those API definitions support category handling, but this read did not find a version-matched Claude CLI contract proving whether `usage.iterations` is complete or additive. Do not aggregate the iteration item with the result until that is checked.
- **Observed and source-backed Codex usage shape.** The selected Codex 0.159.0 two-turn `thread/tokenUsage/updated` stream has first `total.totalTokens=20799` and `last.totalTokens=20799`; the next has `total.totalTokens=41729` and `last.totalTokens=20930`. Its first total also satisfies 20,647 input + 152 output = 20,799, while 6,912 cached input is included in input and 138 reasoning output is included in output. The local 0.159.0 notification schema and pinned public [schema shape](https://github.com/openai/codex/blob/0462dcc062b822bb8fff16cc31ce6eeab69823b9/codex-rs/app-server-protocol/schema/json/v2/ThreadTokenUsageUpdatedNotification.json#L4-L59) declare `total`, `last`, cached input, cache-write input, output, and reasoning output. OpenAI's pinned [token usage source](https://github.com/openai/codex/blob/0462dcc062b822bb8fff16cc31ce6eeab69823b9/codex-rs/tui/src/token_usage.rs#L29-L39) describes `total_token_usage` as accumulated session usage and `last_token_usage` as latest active context size; it subtracts cached input when displaying non-cached input. This source and the two-turn observation support treating repeated `total` notifications as cumulative; they do not establish every 0.159.0 edge case. Cached input is included in input and reasoning output in output in the retained sample, so those fields must not be added to its parent totals. The example does not settle how an interrupted, compacted, resumed, failed, or multi-route episode reports usage. The pinned [account usage response](https://github.com/openai/codex/blob/0462dcc062b822bb8fff16cc31ce6eeab69823b9/codex-rs/app-server-protocol/schema/json/v2/GetAccountTokenUsageResponse.json#L173-L180) describes thread usage as estimated when the billing route is available; rate-limit snapshots are account/window observations, not a per-episode quota debit.

## Feasible candidate input, pending native qualification

The narrow candidate is a version-identified hook input plus a bounded, read-only transcript retrieval at the tool proposal. Preserve event order and roles; relevant user instructions, approvals, amendments, and withdrawals; the concrete assistant proposal needed to resolve a referential answer; and the exact proposed file effect and destination. Resolve location and authorization separately. A `Write` payload can name a destination and content directly; an `apply_patch` or shell payload needs a reviewed, bounded effect parser or must remain unresolved. Relevant target state (existence, content identity, path/symlink resolution, and allowed fixture roots) needs an independent read at the same boundary. Assistant or tool claims of approval are evidence to classify, never user authority. Expected labels and fixture-authored authorization sidecars stay outside candidate input.

No read in this increment establishes transcript append timing, role fidelity after compaction, complete earlier turns, assistant referent visibility, amendment/withdrawal ordering, path safety, truncation behavior, or what happens on missing/malformed records for Claude 2.1.284 or Codex 0.159.0. The smallest proposed native probe is a frozen, disposable staged session per harness. Establish direct approval, then inspect a harmless creation proposal at its PreToolUse boundary. Introduce a concrete assistant proposal and referential user approval before a separately authorized harmless proposal. Amend the destination, then use a separately authorized harmless read or marker call to inspect context; observe any later creation proposal and effect separately. Withdraw approval, then inspect context at another separately authorized harmless read or marker call. Correct non-action after withdrawal may produce **no creation hook**, which is an outcome to record, not a missing observation to force by proposing the withdrawn write. At each actual hook boundary, record event identity, a bounded role/order projection, source size and stable read evidence, parsed proposal, relevant target-state read, and later native effect. A repeated read can test late arrival at the observed boundary. Test absent or malformed input only as bounded parser robustness; it cannot prove native transcript availability. Review the parser and probe before execution. If decisive events cannot be obtained in time, report an unavailable context route; a synthetic sidecar cannot repair that production input gap.

## Whole-episode measurement contract, pending probe

Use one complete task attempt as the unit, including failure or correct non-action. Mark its start and terminal outcome, retain all turns and intervention events, and separately time context retrieval/parse/refresh, each Jev or other model call, agent continuation, retries/reproposals, human interruptions, and manual preparation/recovery. Capture exact call identity and route so repeated notifications and retries can be reconciled. Report per case and per harness before any aggregate. Keep one-time setup and maintenance estimates separate from recurring work, with explicit amortization assumptions if used.

For Claude, start from the result's reported model usage and duration, then check a version-matched CLI result contract or reconcile per-call records against it before aggregating iterations. Treat cache creation/read as separate input classes per Anthropic's API documentation and thinking as a breakdown of output; keep `costBasis="list"` as an estimate. For Codex, require a proven **pre-episode** cumulative baseline and a complete terminal total for the same thread before taking their difference: zero only for a proven fresh thread, or an observed pre-start total for an existing thread. The first post-turn notification is not that baseline. Subtracting 20,799 from 41,729 in the retained two-turn sample yields only the second turn’s 20,930 tokens; it omits the first turn. If a pre-episode baseline or complete endpoint is unavailable, retain the observed snapshots and any partial delta, explicitly account for the uncovered interval, and leave whole-episode usage unknown. Verify the method on fresh and resumed threads before aggregation. Use `last` for diagnosis, not as a second sum. Keep cached input within input and reasoning within output. Account for Jev usage and preparation separately, then reconcile all route subtotals to the episode without treating API latency as end-to-end latency. Label billed money and quota consumption unknown unless a native billing or account control provides attributable evidence. A token reduction alone is a usage claim.

The smallest accounting probe can accompany the frozen native context probe: capture timestamped start/end, all token notifications, CLI result records, Jev request/response usage, hook durations, and manual interaction spans for one successful and one interrupted or incomplete synthetic episode per harness. Compare cumulative snapshots with per-call data and verify cache/reasoning field semantics before arithmetic; a matching sum in one trace is only an observation. If an observable route cannot attribute usage to the episode, report it as a measurement gap rather than a zero. This source read supports designing that probe; it supplies no comparative cost or reliability result.
