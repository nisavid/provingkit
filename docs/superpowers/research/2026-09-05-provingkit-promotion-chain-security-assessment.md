# Provingkit promotion and release-chain audit for public issue #2

This audit establishes that the frozen public source is a coherent seven-member source-stage slate, but it has no current path to one immutable Provingkit release. The chain fails closed before native qualification and final release validation: Task Witness remains production-ineligible, its shipped native/final entrypoints reject those modes, and the Rolecasting and Tricritical provider declarations register validators but no production producer or issuer. ## Authenticated HTTPS executor: answer to issue #4

The frozen source contains a reachable command entrypoint: <code>execute_git_publication.py</code> reads exact reviewed plan bytes and their separately supplied digest, then calls the executor [CLI, lines 1–55][s-vk-cli]. For HTTPS, the executor accepts only a structurally safe endpoint, resolves the captured destination, enables credentials before remote probes and push, rechecks default branch/config/lease, performs one exact push with no blind retry, and verifies the resulting ref [executor, lines 265–387][s-vk-execution].

Its credential boundary is closed rather than ambient: macOS permits a codesign-verified system <code>git-credential-osxkeychain</code>; Linux permits a trusted system <code>git-credential-cache</code> with a credential already in its private memory cache; Windows permits allowlisted Git Credential Manager from the selected machine installation. Unsupported, missing, redirected, or mutable providers fail with <code>HTTPS_CREDENTIAL_PROVIDER_UNAVAILABLE</code> before push. Ambient helpers and unsafe HTTP/credential configuration are cleared or rejected, prompting is disabled, and credential bytes stay in Git's helper protocol rather than plans, arguments, diagnostics, receipts, or repository config. SSH and ancestry-guarded local endpoints retain their separate behavior [execution contract, lines 80–134 and 165–190][s-vk-doc] [macOS/Linux providers, lines 205–265][s-vk-provider-a] [provider selection, lines 1103–1137][s-vk-provider-b].

That is current source reachability, not production validation. The native-provider workflow has read-only repository permission and exercises provider tests; it neither performs a release push nor supplies independent release authority [credential workflow, lines 12–54][s-vk-workflow]. Public #4 says the implementation merged and cross-platform checks exist, but the issue remains open because the independent Daybreak acceptance record is unresolved [implementation checkpoint][i-4-merged]. A later scout found that the PR's clean-review assertion and the durable issue record do not identify the same review artifact [review discrepancy][i-4-discrepancy].

#4 is a hard release gate only if #3 selects Versionkeeping's Git publication executor over authenticated HTTPS for a required source or canonical-state branch ref, #36 must use that route, and no separately accepted actuator can satisfy the contract. Then the exact executor revision, provider boundary on the release host, and reconciled independent review must be accepted before actuation. It is not a hard gate if #3/#36 select an independently accepted SSH/local Versionkeeping route or a different release-ops/GitHub API actuator that does not depend on this HTTPS path. #3 owns that route/contract choice; #36 owns operational revalidation and use; #4 owns its security-review evidence. The native graph's lack of #4 edges cannot choose among them. The ordinary branch publication of the audit checkpoint did not exercise Versionkeeping and validates none of this [checkpoint publication note][i-2-published].

## Static validation rubric

1. Preserve one exact claim identity and name the accepted sink.
2. Trace source/configuration through registries, entrypoints, callers, tests, and workflows to that sink.
3. State preconditions, the product trust boundary, and the independent authority required.
4. Separate supporting evidence, counterevidence, and existing/missing/stale/fixture-only proof.
5. Record the proof gap, confidence, disposition, and smallest owner-correct next step.

The method below is static source/config/caller/test/workflow tracing in the frozen export. It is not dynamic validation, production qualification, credential testing, or a repository-wide vulnerability scan.
