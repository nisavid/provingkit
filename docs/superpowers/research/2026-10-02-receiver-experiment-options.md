investigating the missing qualification observations in parallel. The reviewed
reader and hook are useful source candidates. Neither is ready to operate on
Desktop, and the route still lacks live delivery and full-state evidence.

## Two tracks for the next increment

### Prepare a bounded fixture check

The smallest useful live proposal would test **fixture identity and Stop output
without a cross-harness notification**. It would still create a disposable task,
change project hook configuration, execute a collector command, issue a setup
prompt, and acquire private event and selected metadata bytes. Those effects
need an enumerated plan, review, and a separate live grant.

Preparation should deliver:

1. **Collector mechanics.** A concrete command/runtime, input-size ceiling,
   selected output fields, private sink and retention, interruption behavior,
   and evidence of when and for which fixture the collector ran. Review the
   acquisition before projection. The full Stop input can include cwd,
   transcript path, permission mode, assistant text, background commands, and
   cron prompts. The prototype currently accepts an already supplied object.
2. **Configuration and executor binding.** Name the dedicated project and exact
   settings file, preserve its other hooks, and establish how this selected
   Desktop executor loads the change. Name the minimal observations needed to
   distinguish an embedded target from the executable actually used. Additional
   process or executable reads belong in the proposed grant.
3. **An independent fixture witness.** Specify how the operator or authorized UI
   controller selects the disposable Desktop task. Give its setup prompt a
   unique response token. Propose an explicit environment-field allowlist for
   the collector, including the inbox path if needed, then uniquely join the
   observed Code identity to a selected metadata record's current Code identity.
   A title, recent filename, prior lineage, or sender-asserted host ID is not
   enough. No unique join means an unresolved identity.
4. **Exact acquisition bounds.** Consider the research proposal: one bound
   account/organization directory; a nonrecursive listing of at most 128 entries
   plus an overflow entry; at most three explicitly selected metadata files;
   at most 1 MiB plus one overflow byte per file. These are proposed limits,
   not an adopted grant. Opening each file acquires all its serialized private
   fields. List the actual files or selection rule and bytes in the final packet.
   No unrelated transcript is needed for this check; any fixture transcript
   read would need its own purpose and explicit scope.
5. **Expected observations and failure handling.** Seek one selected executor,
   one Desktop/current-Code/endpoint association, an observed hook invocation,
   and the setup response's actual Stop representation. Missing, duplicate,
   stale, or conflicting evidence remains unknown. This establishes neither
   delivery nor full-state preservation, even if every observation succeeds.
6. **Restoration and resource cost.** Specify collector shutdown, removal of the
   temporary configuration while preserving concurrent changes and other hooks,
   disposition of private records and temporary files, and fixture closeout.
   The setup prompt consumes a model turn. Hook loading, interruption, and total
   duration are unmeasured. Preparation must determine whether a restart is
   needed; it must not inherit the old two-restart plan or its 15-minute deadline.

The wrapper introduces I/O and lifecycle behavior beyond the pure hook seam.
Agree its public test boundary before implementation through `tdd`, then use
invented events and disposable files. Fixture preparation can progress without
knowing every preservation producer, provided its eventual live claim remains
this small and returns for approval.

### Resolve specific qualification gaps

In parallel, produce a requirement-to-producer design for authenticated account,
model semantics, complete applied permissions and pending changes, worktree/cwd,
and access to the selected query. Reuse the inspected engine handlers and
Desktop evaluators. State the authoritative producer, exact observation path,
field meaning, lifecycle binding, timing, and smallest check still needed.

If existing interfaces cannot expose a producer, compare a temporary diagnostic
adapter with an ongoing dependency for that particular gap. Transfer evidence
must show why an instrumented observation applies to ordinary Desktop: identify
the unchanged producer and path, any perturbation introduced by the adapter,
and the ordinary-build observation or comparison needed. A source patch or
synthetic callback alone cannot establish that transfer. If no producer has the
required meaning, return the requirement and alternatives for a decision.

## Choices and costs

| Next choice | Benefit | Cost or limit |
| --- | --- | --- |
| Prepare the fixture check and investigate state in parallel — recommended | Turns known source paths into a reviewable experiment while preserving progress on the qualification blockers | Two bounded tracks to coordinate; the fixture may reveal loading or identity problems and still cannot qualify the route |
| Resolve state producers before preparing a fixture | Avoids collector preparation if the full contract proves infeasible | Delays direct evidence of selected-executor, hook, and task binding; those uncertainties remain regardless |
| Develop a specific temporary app observer now | Could expose an otherwise inaccessible selected query or host evaluator | Requires choosing its exact missing producer first; adds app changes, restoration, and transfer evidence without solving missing semantics by itself |

The comparison does not recommend broad `ListAgents` discovery for this small
check: its registry/process/socket access and possible stale-record cleanup add
effects, and constructing an exact socket selector does not require it. SDK
directory helpers similarly need their acquisition footprint justified before
use. Neither is permanently ruled out. StatusLine is not an established
headless producer in the inspected artifact. An ongoing app patch has no
demonstrated necessity for ordinary notification evidence at this point.

## Join and decision

The experiment decision should first record the operator's reaction to the
prototype, then select preparation scope, proposed discovery bounds, and any
new test boundary. Keep fixture preparation and runtime-state design separately
owned, with frozen inputs and a cross-examination join. The revised probe packet
must reconcile both results before presenting a live grant; any unresolved
full-state field continues to block qualification, even if a narrower fixture
experiment is separately selected. Continue through the existing preparation,
authorization, evidence, and interface gates.

Use `capturing-agent-procedures` when consuming this comparison. Load the
published source revision and its contract before design. The reusable lesson
already filed with [the agent-panel workflow catalog](https://github.com/nisavid/provingkit/issues/306#issuecomment-5962116278)
is to trace the real producer through forwarding and persistence before trusting
a synthetic specimen. This comparison adds a decision step: separate which
uncertainty an experiment can resolve from the larger qualification claim it
cannot yet support. Broader codification remains with that catalog's owner.
