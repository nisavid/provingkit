## Writer ownership and independent readback

WriterLockCoordinator uses the selected Codex home plus thread-writer-locks and a native-thread lock filename, coordinated through .coordination.lock. acquire returns WouldBlock when that lock is held; guard lifetime retains ownership through file work. Local create/resume acquires the writer lock before creating or reopening the recorder. This is writer exclusion among participating implementations sharing that namespace. It does not prove cross-home exclusion, queue-store exclusion, a runner/approval-owner lease, actual GUI participation, or safe coexistence for a particular installed runtime. [Writer lock, lines 17–85 and 174–195](https://github.com/openai/codex/blob/97239fd052db455bd08c41afcdab738e0fe83b87/codex-rs/rollout/src/writer_lock.rs#L17), [local writer, lines 24–136](https://github.com/openai/codex/blob/97239fd052db455bd08c41afcdab738e0fe83b87/codex-rs/thread-store/src/local/live_writer.rs#L24).

Resume can ignore mismatched overrides while a loaded thread remains observable, or shut down an eligible idle cache entry without subscribers and resume cold after complete shutdown. Cold resume can load project/configuration dependencies and invoke idle work; loaded rejoin starts/uses a listener and changes client information. History/path alternatives can override requested-ID selection for cold resume. Use the supplied native ID without those alternatives and verify the resolved ID; a shared session-tree ID is not the individual thread identity. [Current resume, lines 3839–4455 and 4497–4808](https://github.com/openai/codex/blob/97239fd052db455bd08c41afcdab738e0fe83b87/codex-rs/app-server/src/request_processors/thread_processor.rs#L3839).

Unsupported history methods, missing materialization, stale cursors, null timestamps, and changing pages remain limits.
