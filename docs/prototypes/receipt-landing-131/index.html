Keep the Receipt through landing

Can the actual landed source use its unchanged evaluation Receipt after squash, while rejecting changes to the inputs and preserving the original evidence?

This page replays results measured by real disposable Git fixtures. Buttons select those observations; they do not execute Git, evaluate a model, or simulate a passing check. The accepted direction goes into a separate strategy decision.

    My recommendation for discussion

    Keep squash and develop explicit input correspondence, with retained evaluated source and processing provenance, the original comparison, and an independent check of the actual landed commit. A fresh consumer needs a fetchable retained reference or source archive; a digest alone cannot recover missing history.

    An ancestry-preserving merge is the simpler alternative for the Receipt adapter. It still needs the final-commit consumer and would require changing the currently allowed merge operations. Fast-forward only fails when the target diverges; ordinary rebasing does not guarantee the evaluated commit survives.

    I accepted correspondence and retained provenance as the direction for #132. That response does not adopt the strategy or authorize migration; final independent and coordination review are still required to close the prototype question.
