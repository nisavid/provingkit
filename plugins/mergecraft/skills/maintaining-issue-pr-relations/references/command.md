# Relation Command Interface

Schema version 1 binds supplied contribution decisions to observations, plans,
and separately authorized effects. Read [the relation contract](relation-contract.md)
for contribution, closure, and publication policy.

`python plugins/mergecraft/skills/maintaining-issue-pr-relations/scripts/relation_state.py observe|plan|reconcile --input FILE [--state-root DIR]`

Files contain UTF-8 JSON. CLI prints exactly one JSON result. Exit 0: observed, ready, verified, no-op. Exit 1: needs-input, blocked, partial, unknown. Public Python seam: `execute(command, document, forge=None, state_root=None, now=None)`; injected forge is the external boundary. Production needs authenticated `gh` on PATH. `now` accepts an ISO timestamp with timezone and exists for deterministic callers/tests.

`observe` request: `{version:1, task_id:string, applicability:{active:boolean, reason:enum}, pairs:[], entity_observations?:{id:entity}, setting_observations?:[], setting_ttl_days?:30|null, invalidate_settings?:[], body_edits?:[], native_selection?:[]}`. Reasons: unrelated-edit, no-contribution, unchanged-relations, relation-change, historical-repair, setting-refresh. Only the first three allow `active:false`. Inactive requests cannot contain pairs, body edits, or invalidations. A task ID remains stable across resumes. Default state is `$XDG_STATE_HOME/mergecraft/issue-pr-relations` (fallback `~/.local/state/mergecraft/issue-pr-relations`). Test callers must supply a temporary state root.

Each pair has issue/pr references `{host:github.com, repository:owner/name, number:positive integer, id:opaque node ID}`, intent ensure|unlink-native|withdraw, evidence nonempty string array. Retained contributions require role:string and completion:partial|complete; complete additionally requires completion_evidence:nonempty string array. Withdraw requires withdrawal_reason:mistaken-association|scope-dropped. Cross-repository pairs involving private repositories require disclosure_authorized:true. This is an explicit evidence boundary, not inferred authority.

Complete reused entities have id, host, number, kind Issue|PullRequest, url, title, body, state, repository:{id,name,visibility:PUBLIC|PRIVATE,default_branch}, relations:{all:[],manual:[],detected:[]}, pagination_complete:true. PRs also have is_draft, base_ref, head_oid. Reuse is caller-bound to the active work observation; writes independently reobserve the affected entities.

Setting observations may use `{host,repository_id,auto_close:boolean|null,observed_at,source:github-settings-ui,evidence:[]}`. `auto_close:false` means disabled; `auto_close:true` means enabled. A selected task observation remains usable for every later dependent effect in that task unless explicitly invalidated; becoming needed later does not cause acquisition. The helper owns cache selection and expiry. Verified rollout records are accepted directly: `{host,repository_id,repository,value:boolean,observed_at,source:https://github.com/owner/name/settings,status:changed-verified|already-disabled-verified|verified}`. Original time/source persist; resupplying old observations does not renew their age. Only confirmed booleans persist across tasks. An auto_close:null supplied observation records an unavailable acquisition for the current task, suppresses another attempt there, and does not suppress acquisition in a later task. Unneeded observations are ignored. `invalidate_settings` entries have host,repository_id,reason:explicit-refresh|observed-change|contradictory-behavior,event_id; event IDs make replay idempotent. First observation of an invalidation event records a freshness boundary; supplied observations at or before that boundary cannot reinstall the invalidated value, including when retained in the same replayed request. A new UI observation must be later than the boundary. Setting requests are emitted at most once per needed repo/task; no detector or browser is invoked. Existing partial closing edges are closure-sensitive too. Complete fixes skip setting lookup.

`observe` returns status observed, request, entities, settings, setting_requests, read_counts. `entities` and `connection_pages` count acquired logical entities and pages; reusing a complete supplied entity adds zero to both. `settings` is always 0 because the helper emits acquisition requests instead of reading Settings. `external_read_requests` and `external_write_requests` count actual adapter requests separately. The production adapter groups each endpoint and all/manual/detected first-page aliases in one GraphQL request and paginates only remaining pages.

`plan` consumes the complete observation and performs no forge/cache access. Returns status ready|needs-input|no-op, request (only execution decisions), decisions, entities, settings, effects, ledgers, handoffs, omitted_native, read_counts, plan_sha256. The digest binds canonical sorted compact UTF-8 JSON excluding plan_sha256. `effects` kinds: issue-body, native-add, native-remove. Each has an effect_id over its canonical JSON excluding effect_id. Native effects have issue_id,pr_ids (max10); the ten-manual-Issues-per-PR capacity is independent. Optional native_selection is an explicit array of {issue_id,pr_id} pairs for capacity overflow. Complete body ledgers retain all supplied evidenced contributions even where native links are omitted.

Body decisions are separately authored: `{entity_id, expected_body_sha256, start_byte, end_byte, before, replacement, candidate_body, writer, evidence}`. Offsets are half-open UTF-8 bytes; candidate_body must equal the complete observed body after replacing bytes [start_byte, end_byte) with replacement, and is sent unchanged. Issue writer: writing-github-issue-and-pr-markdown. PR writer: writing-reviewable-pr-descriptions. Missing decisions produce body-authoring handoffs with writer, entries, withdrawals, and complete preimage_body. The command does not parse Markdown or infer a ledger boundary. Suspected secrets block candidate publication through the existing shared scanner.

PR effects are always `kind:pr-publisher` handoffs carrying `schema_version:1, operation:pr-relation-ledger-write, target:{host,repository,repository_id,entity_id,number}, preimage:{title,body,state,is_draft}, authorized_span:{start_utf8,end_utf8,replacement}, candidate:{title_sha256,body_sha256}, candidate_body`, plus author/evidence/before-body digest. The caller adds review:{mode,selected_specialists}, supplies literal complete title/body files to the existing publisher, then resumes. Core never writes PR content. Handoffs also include pr-keyword-removal, native-selection, and closing-intent-decision. Existing partial enabled/unknown links require an owner decision; they are never automatically removed.

`reconcile` consumes `{version:1, plan, authorization:{plan_sha256,effect_ids:[],renewals?:[]}, publication_results?:[], mode?:apply|observe}`. Plan is rebuilt from its retained decisions before any remote access. Pending owner handoffs return needs-input. Publisher results use schema_version1, operation pr-relation-ledger, exact target fields, before_body_sha256,after_body_sha256,title_sha256,state,is_draft,status verified|blocked|unknown,no_op,receipt_id,receipt_sha256. Non-no-op verified results need receipt identity/digest. Reconciliation independently reobserves complete PR content/state and all relation provenance, so a publisher claim alone does not prove success.

After normal canonical PR creation or update, obtain a fresh `observe` result and `plan` with the writer's already-correct PR ledger represented as an unchanged body decision. That plan has no `pr-publisher` handoff for the PR and needs no `publication_results` entry for it. Keep canonical receipts in the lifecycle context; they are not ledger-publication receipts.

For each authorized core effect, reconciliation rechecks the affected complete preimage, validates the selected setting generations inside the same locked local transaction that reserves the attempt, writes at most once, then independently rereads. It never closes/reopens an Issue. Already observed postimages return no-op, not a causal claim. Errors plus data are errors; timeout/ambiguous responses are unknown; partial effects remain explicit. No server-side compare-and-swap or transactionality is claimed. A concurrent edit between preflight and mutation cannot be eliminated by this API; unexpected postimages block/return partial without rollback.

Core recovery: `mode:observe` is read-only on the forge and remains available after the plan's setting generation is invalidated. It grants no renewed write authority. A retained attempt whose exact preimage remains visible produces needs-input and an effect result containing effect_id, attempt_id, receipt_id,receipt_sha256, position:preimage, preimage_sha256, observed_at, reason:prior-attempt-observed-preimage. Its observation receipt is persisted locally. A newly and explicitly authorized apply may include `authorization.renewals:[{effect_id,attempt_id,receipt_id,receipt_sha256}]`. The command rereads the current preimage, validates the receipt and current settings under the state lock, and atomically reserves the next attempt before writing. Prior attempts remain in history; receipts cannot renew a later attempt. `mode:observe` with an already observed postimage returns no-op.

A native batch that visibly applied only a proper subset has a narrower recovery path. Observe may consume either the original plan or a fresh plan for the exact remaining effect. It rereads every original endpoint, including completed PRs omitted from the fresh plan, and requires every unrelated field and provenance edge to match the retained original fingerprint. Its result has reason:prior-attempt-observed-partial, position:partial, original_effect_id, original_endpoint_ids, applied_pr_ids, remaining_pr_ids, remaining_effect_id, and the ordinary attempt/receipt identity, timestamp, and fingerprint digest. The output effect_id still identifies the effect being observed; authorize renewal using remaining_effect_id. This distinction matters when observing the original complete batch.

To continue, construct a fresh safe plan with exactly that remaining native effect and explicitly authorize it with the receipt through the existing renewals array. The command again rereads all original endpoints, validates the receipt and selected setting generations under one state lock, marks the original attempt superseded-by-authorized-remainder, and installs the new remainder attempt atomically. Both attempts and the linking receipt remain in local history. The original full batch cannot be replayed, and missing or altered receipts do not authorize the remainder. Unrelated drift, multiple overlapping attempts, or another repartition remain held. New pending attempts retain the fingerprints needed for subset recovery; a legacy pending record without them remains held rather than fabricating evidence.

The initial and renewed reservations use fsync plus atomic replace; POSIX directory metadata is also flushed. An interruption after remainder admission leaves the new attempt pending. Its own read-only preimage receipt and a separate explicit renewal are required before another write. No file deletion, automatic retry, unrestricted retry flag, server-side compare-and-swap, or remote transactionality is claimed.

Scope: qualified github.com repositories, supported manual native links and exact Issue-body spans. No unsupported settings API, permissions-role emulation, general Markdown inference, commit rewriting, PR state change, title editing, or Issue close/reopen. Detected closing keyword removal belongs to its content owner and requires a fresh observation/plan after completion. Caller/semantic writers remain responsible for complete finite contribution evidence and authorized ledger boundaries. Windows local locking code exists but was not exercised in this Linux test run.
