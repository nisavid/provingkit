# Forward a held reply through a native control

Use this procedure when you already hold the complete addressed reply,
including at an intermediary in the intended recipient's harness. The
original sender and actual submitting actor remain distinct.

1. Inspect the original operation using its retained binding before choosing a
   route. An unresolved attempt goes to [observation](#observe-the-original-attempt).
   Keep a recorded refusal on its original attempt. If you cannot establish
   the original attempt state, report the missing record and its custodian.
2. For an eligible new attempt, resolve the native recipient using trusted
   caller-side evidence. Verify the exact conversation, host and any applicable
   account binding. If the recipient is ambiguous, ask only for the missing
   selection. If native reachability cannot be verified, use another
   maintained procedure only when it already covers the requested operation
   and its permission. Otherwise report the exact missing control or binding.
   Endpoint preparation belongs to the selected transport.
3. Check the actual native send's requirements and current permission for this
   actor, recipient and payload. A peer's report of permission and a case
   reference carry information only. If the actual send cannot verify
   permission, identify the required grant and stop before submission.
   Persist the claim with the [retained mailbox procedure](native-codex-mailbox.md).
   Use the original store or its explicitly bound private location for first
   setup. Keep store preparation with the caller.
4. Use the native send once under the existing settings. Carry the unchanged
   reply with its original sender, correlation and holds, and record the
   actual submitting actor. Use the [peer envelope](peer-messages.md) when
   the native control transports the reply as text. Supply only fields that
   control accepts. A bound native send requires no nominated endpoint.
5. Record the original result. An explicit refusal before submission is a
   refusal. A lost or ambiguous result after a possible send remains unknown.
   A successful submission advances only submission. Preserve the native
   reference if returned. These outcomes stay on the original attempt.

## Observe the original attempt

Use the retained peer and correlation to verify the exact observation target,
control and read permission separately from any permission to send. Use the
bounded matching observation for an unresolved attempt or a requested receipt
or reply. The [mailbox procedure](native-codex-mailbox.md#reconciliation-and-replacement-intake)
describes Codex read and wait where exposed. If matching observation is
unavailable or ends without a match, leave the operation pending and return
the original references and the named continuation owner. Record receipt,
handling and reply only from matching evidence.
