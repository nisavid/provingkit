# Jev Suitability

Consider Jev first only when the complete narrow operation is a System One typed text judgment: a specified typed question over supplied state can return a structured answer and probabilities. A typed substep does not make an operation suitable when its result also requires open-ended analysis, prose, tools, action, or later synthesis in the same bounded assignment.

Keep an existing deterministic exact procedure when no semantic judgment is needed. A Jev label may inform triage, but does not complete a broader vulnerability, protection, or review claim. Define the answer choices or scale and a disposition for uncertainty that fits the data and consequences. [TypeSafe's Jev introduction](https://docs.typesafe.ai/introduction), [question types](https://docs.typesafe.ai/primitives), and [confidence guidance](https://docs.typesafe.ai/confidence) describe its typed answers, probabilities, and domain-specific confidence thresholds. Do not hardcode a universal threshold.

Suitability does not prove current availability, exact target capability, or authority. Require those independent gates before invoking Jev. When Jev is unavailable, continue to the applicable security or general route and do not claim a live Jev result. A model advertised as Jev without a proven executable route is unavailable for this selection.
