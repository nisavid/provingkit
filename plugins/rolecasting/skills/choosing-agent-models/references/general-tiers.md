# General Model Tiers

The published-text rule applies to authorship on every route. Use these tiers only for work outside the three security classes after checking complete-operation Jev suitability. Outside published-text authorship, among pairs that fit the applicable casting rule, select the lowest-cost proven pair preserving the assignment's judgment margin. Assess workers by task fit; use the role-specific defaults below for operational coordination and intake. The comparisons here are operator guidance and observations, not benchmark results or proof of live settings.

## Cast by the next decision

Cast the worker by the judgment the next decision needs. Use the economical tiers for tasks that fit them and the specific role bindings for the roles they cover.

- Select GPT-6.2 Sol when the caster can name an observation that shows the current increment is complete and a test can check it. Start precise, recoverable work at a supported `medium` when sufficient. Never default to Sol on an uncertain match.
- Name GPT-6.2 Astra when identifying that observation takes judgment. Name Astra for strategy, hard technical problems, creative execution, or review even when a test can verify the result. On Impeccable briefs that use the lead-and-executor split, follow the [creative role bindings](#creative-roles). For a second opinion on Sol's work, default to Astra. Use Claude Opus 5.5 for that second opinion only when Codex routing or quota is unavailable. Opus is not a technical default and must not interpret intent.
- Start Claude Fable 5.2 at `high` for unforeseen judgment, direction, policy, intake and framing, or creative leadership. State why the assignment needs `xhigh` before selecting it. Apply the existing [Max effort policy](effort-policy.md#max-effort) and require a current successful [Fable target proof](capability-probes-and-fallbacks.md#prove-fable).

GPT models take long, low-judgment web flows and exploratory testing. The delegating agent that hands such a flow off still reads for itself any page it needs as evidence.

Among pairs that fit the applicable casting rule, prefer Claude for UI, UX, and visual design, and GPT for review. Before dispatch, when an eligible and authorized other-provider target would satisfy the preference, recommend target reconsideration to the owning delegating workflow and wait for its revised plan before selecting on that target. Do not silently change the settled worker target. An explicitly operator-fixed target or the sole eligible target remains in force. Disclose the preference limit and select a proven pair there only if it fits the assignment.

## Published text

Published text speaks for the project and its operator to readers who cannot ask the writer what was meant. Apply the writer rule to every text intended for publication, including commit messages, source code comments, pull request and issue titles, descriptions, and comments, review replies, plugin and package descriptions, documentation, and release notes.

| Kind of published text | Preferred writer | Also allowed | Everyone else |
| --- | --- | --- | --- |
| Routine, mechanical, or mediocrity-tolerant prose, such as source code comments and commit messages | Opus or Sol | Fable or Astra | Excluded |
| Pull request and issue titles and descriptions | Fable or Astra | Opus or Sol | Excluded |
| Pull request and issue comments that publish or announce an update or a note to no one in particular, or that address or reply to a bot | Fable or Astra | Opus or Sol | Excluded |
| Comments addressing or replying to a person | Fable or Astra | None | Excluded |
| High-impact, high-consequence, or highly quality-sensitive creative work, such as a plugin description | Fable or Astra | None | Excluded |

Choose a preferred writer if available. Otherwise choose an also-allowed writer. If neither is available, there is no eligible writer.

Treat the current Sol as Opus's equal in every row. Sonnet writes no published text. Apply the maintainer's rule with these three interpretations:

- Fable or Astra may also write routine prose.
- Terra, Haiku, Luna, and Grok share Sonnet's exclusion.
- For an unlisted kind, use the nearest row. When two rows fit, use the stricter one.

Any model may apply a qualified writer's text word for word under the applicable action authority. Changing the wording is writing.

## Economical frontier and task fit

Compare useful cost, latency, and capability points within the task's quality and judgment requirements:

| Pair | Selection guidance |
| --- | --- |
| GPT-6 Luna `high` | Lower end of this comparison. Exclude Luna `xhigh` and `max` from consideration. |
| GPT-6.1 Terra `low` (Light) | About Luna `max` capability at much lower cost and latency; replaces Luna `max` and `xhigh`. Use only when task fit and judgment margin suffice. |
| GPT-6.1 Terra `medium` | Similar cost and latency to Sol Light with somewhat stronger capability; replaces Sol Light. |
| GPT-6.1 Terra `high` | Useful frontier point approaching Sol `medium` capability. |
| GPT-6.2 Sol `medium` | Prefer over Terra `xhigh`; this preference does not declare Terra `xhigh` unsupported. |

Terra Low/Medium/High bridge Luna High to Sol Medium. Terra is somewhat less capable at the top end than Sonnet 5.5 but substantially cheaper. Preserve outcome quality ahead of price; these comparisons do not impose a universal ranking across unlike tasks. For work other than writing published text, use Claude Sonnet 5.5 for some-complexity work beyond Haiku/Luna that shallow cognition can resolve without sensitivity to outcome quality. Outside published-text authorship, route deeper reasoning or quality-sensitive outcomes to a suitable stronger pair, using the [next decision](#cast-by-the-next-decision) to select the worker. For writing, follow the [published-text writer rule](#published-text) whenever the text is intended for publication.

Sonnet and Haiku are outside the named-family medium floor and ineligible for `max` under [effort eligibility](effort-policy.md).

- **Committed code:** Terra is not an ordinary authoring default. Only `medium` or `high` may fit a narrowly predictable, contained, easy assignment with a clear judgment margin; `low` is outside this exception.
- **Computer and browser use:** consider Terra strongly for speed, price, and competence; the operator observes particularly fluid browser use at `medium`. Preserve actual correctness and interaction requirements.
- **Low-poly 3D modeling and animation:** consider Terra for spatially coherent, accurate prototypes and first passes, including animation. Validate the prototype before handing off elaboration, refinement, and polish. Cast that worker by the next decision. Terra is not the detail or polish lane.

Consider Claude Haiku 5.5 for simple, well-understood classification, extraction, and routing. For these bounded worker tasks, choose the lowest supported effort that preserves judgment and outcome quality. Eligible Luna and Grok pairs are also candidates when task fit permits. Grok 4.7 `high` may fit moderately complex, well-understood work within its role. Apply [effort eligibility](effort-policy.md) and [native label binding](capability-probes-and-fallbacks.md#prove-an-exact-pair) to every choice.

## Coordination and intake roles

Use these operating defaults for coordination and intake:

| Role | Codex | Claude |
| --- | --- | --- |
| Orchestrator | Terra 6.1 `medium` | Sonnet 5.5 `medium` |
| Dispatch | Terra 6.1 `low` | Haiku 5.5 `high` |
| Concierge | Terra 6.1 `medium` | Haiku 5.5 `xhigh` |
| Scoped operator-owned Reception | Sol 6.2 `high` | Opus 5.5 `high` |

A coordinating role assigns, tracks, and verifies the work. Workers carry it out. The coordinator writes no published text of its own, whatever model it runs on.

The orchestrator and Dispatch defaults assume Sage support for continuing intellectual leadership. For orchestrators, reserve `low` for demonstrably settled, simple coordination and `high` for difficult coordination itself. Route bounded demanding analysis to a worker cast by the next decision and continuing intellectual leadership or specialty arbitration to a Sage or Advisor. Keep these assignments separate from the orchestrator's coordination effort. Apply Terra's committed-code exception and other family effort rules independently.

Concierge uses its own effort for accurate routing and handoff. Route requests that need careful framing to scoped Reception, which assigns the framing work under the worker rules above. Check each Claude executor for the selected Haiku effort, including `xhigh` for Concierge.

The current operational Codex Foreman is an orchestrator. Target decision-facing Foremen are operator-owned harness-wide Sages with the adopted Astra 6.2 `ultra` and target Fable 5.2 `ultracode` selections. Their operational duties transfer only through accepted cutover; preserve these separate bindings rather than lowering them as orchestrators. These Sage policy selections do not establish effective native settings or activation. If the exact native model, effort, or required toggle is unsupported, retain an accepted interim through the owning workflow; add no proof-only invocation or cutover gate.

Treat defaults as selected policy. Verify supported model/effort controls, effective selection, and persistence separately; acceptance of a configuration request proves none of the other observations. Source guidance neither activates nor transfers a role. Evaluate missed escalation, authority and hold preservation, outcome quality, and total orchestration, handoff, recovery, and model cost under [#740](https://github.com/nisavid/provingkit/issues/740). The Sage serial/delegation and resource-stewardship study under [#804](https://github.com/nisavid/provingkit/issues/804) informs later guidance without becoming a current cutover prerequisite; no new experiment is required for this cutover.

## Creative roles

Use these selections for a brief that runs on Impeccable's lead-and-executor split. They are role bindings for that brief. The stack that owns the repository the brief changes casts them; they create no standing seat.

| Role | Selection |
| --- | --- |
| Creative lead: the direction contract and the comp round | Fable 5.2 `high` |
| Comp approval, where the medium has a comp | The operator. No model approves in the operator's place. |
| Executor: everything between the approved direction and the finish review | Astra 6.2 `high` where a route carries the medium; otherwise the lead's session builds |
| Finish reviewer | Fable 5.2 `high`, in a fresh context that did not write the contract |

Check that a route carries the medium before casting an executor outside the lead's harness. Work the executor returns as text travels on any route that returns text. A built surface also needs the executor's harness to hold the same Impeccable version and engine as the lead's, with write access and a way to capture. Verify these on the target, and do not infer them from the model's capability or from another surface.

Impeccable's shipped agents declare `model: inherit`, so each takes the model of the session that starts it. Cast that session, or pass the model where the creation surface has a model field.

The lead takes work back on the three signals the equipment already gives: a `rebuild` disposition, two misses on one plate, or a gate that names its route after three failed attempts. It takes back the named regions or the first viewport, never the whole surface.

For a medium with no comp, the lead hands the executor two exemplars and one near miss with its reason, beside the contract. An exemplar states no fact the contract does not give. When the executor's harness has its own installed Impeccable, the brief says that the contract in the prompt governs.

Each brief records the model and effort that ran in each role, what the executor decided on its own, the review's disposition words, and the number of rebuilds.

This section governs the executor on such a brief over the general preference for Claude on UI, UX, and visual design. That preference still governs the lead, the finish reviewer, and design work outside the split. Apply [effort eligibility](effort-policy.md) and the [Fable target proof](capability-probes-and-fallbacks.md#prove-fable) as elsewhere; an effort above `high` needs a stated reason.

## Exceptional cognitive work

The [published-text writer rule](#published-text) governs authorship independently of the cognitive threshold below. For published creative work, any one of high impact, high consequence, or high sensitivity to quality requires Astra or Fable.

For work outside published-text authorship, the next-decision selections, and the named role bindings above, reserve GPT-6.2 Astra or Claude Fable 5.2 for work that is both **high-stakes** and demands at least one of deep cognition, intuitive hypothesis, analysis or synthesis, thoughtful articulation, or judgment over substantial unknown unknowns. Casting Astra or Fable by the next decision selects the model alone, including when creative execution also qualifies as published creative work. Apply every [`max` gate](effort-policy.md#max-effort), counting the role as exceptional only if the assignment independently meets this high-stakes conjunction, is published creative work meeting any one of the three conditions above, or uses Fable as the [authorized deep-cognition fallback when Daybreak Blue is unavailable](daybreak-routing.md#unavailable-daybreak-blue). Astra is the more economical exceptional option; use it for a bounded assignment that preserves the high-stakes judgment, not to enlarge scope. Use Fable for choicest beneficial deep work only with a current successful [target proof](capability-probes-and-fallbacks.md#prove-fable). This general-tier conjunction does not replace the more specific Fable security fallback rule.
