# Completeness and synthesis

## Dynamic risk specialists

Select required read-only critic axes and risk specialists from the frozen
current increment, not from a fixed always-on list. Expand the plan only for a
material current-increment concern. Available specialist families include:

- security/authority
- persistence/migration
- accessibility/user impact
- performance/concurrency
- release/operations

Run every selected specialist as a separate read-only execution routed through the closest existing public critic skill. Give it the same frozen review input and byte-identical candidate, and isolate it from all other reports. A specialist is an execution role, not a new public skill identity or reverse edge.

After candidate or evidence changes, rerun every selected scope whose declared
dependency identity changed. A dependency-proven unchanged scope may retain its
prior usable report only when its prior report identity, unchanged dependency
identities, and explicit unchanged proof are preserved. Fresh and retained
scopes together must exactly cover the frozen reviewer scopes.

## Completeness

If any selected critic or risk specialist fails, times out, exhausts its
bounded execution budget, or returns an unusable report, preserve the raw
failure, name the missing axis or specialist, and mark the ensemble explicitly
`incomplete / non-clean`. Do not hide the gap, silently retry, or start a retry
loop. Include every selected critic and specialist in the completeness
accounting.

## Synthesis

Preserve raw reports. Deduplicate only findings with the same evidenced cause. Independent corroboration increases attention only; it is not automatic truth and does not automatically raise severity. Resolve disagreement with direct evidence from the frozen source, never by averaging reports. If the evidence does not resolve a disagreement, retain it and state the uncertainty.
